> сессию. Сквозные правила — в корне; этот файл читается перед задачей в своей

## Пакеты иконок

Пакет иконок — **реализация контракта**, а не мешок SVG. Контракт — список
ролей в `packages/setup/content/icons/roles.ts` (`ICON_ROLES`): `check`,
`checkIndeterminate`, `close`, `arrowDown`, `arrowRight`, `arrowsOutward` и
`arrowsInward` (кнопка разворота модального окна), `calendar`
(кнопка календаря DatePicker), `arrowUpward` (отметка сортировки в заголовке
колонки Table: по убыванию её поворачивает тема), `star` (звезда Rating —
одна на пустой и залитый слой: их красит тема), `minus` и `plus` (кнопки шага
NumberInput «меньше» и «больше»: глифы «−» и «+», а не шевроны — рядом они
читались бы как «раскрыть»), `error` (значок у текста
ошибки поля формы Field: в режиме принудительных цветов ошибку от подсказки
отличает только он; он же — значок вида `error` тоста), `notification`,
`info`, `success` и `warning` (значки остальных видов тоста Toasts — обычного
сообщения, сведений, успеха и предупреждения: в режиме принудительных цветов
вид различает только глиф, поэтому роль у каждого своя). Ровно как тема
реализует классы, которые soldy выпускает в разметку.

Добавили иконку в новый компонент — добавьте роль в `ICON_ROLES`, и
conformance-тест сразу покажет, какие пакеты её ещё не закрыли.

**Формат — данные, не разметка:**

```ts
export const close: TIconSource = {
  viewBox: '0 -960 960 960',
  body: '<g fill="var(--so-icon-color, #1f1f1f)"><path d="M480-424 284-228q…"/></g>',
}
```

`body` — содержимое `<svg>` без самого тега, поэтому корень строит адаптер и
может задать размер, `aria-hidden` и классы. Отдай пакет целую строку
`<svg>…</svg>` — всё это стало бы недоступно.

Два ограничения, из-за которых формат именно такой:

- **никакой магии сборщика.** Прежний `import './close.svg?raw'` понимал
  только Vite: опубликуй пакет — и потребитель на webpack или в Node получит
  ошибку разрешения модуля;
- **никакого рантайм-компилятора.** Адаптер строит разметку через `h()`, а не
  `template`. Раньше из-за `defineComponent({ template: svg })` в конфиге стоял
  алиас на полный билд Vue — иконки навязывали лишний вес каждому приложению и
  ломались при CSP без `unsafe-eval`.

**Пакет подключает приложение, как тему:**

```ts
import { useIcons } from '@soldy-ui/setup'
import * as material from '@soldy-ui/icons-material'

useIcons(material)
useIcons({ close: myCloseIcon }) // точечно, поверх набора
```

Без вызова компоненты рисуют пустую заглушку и один раз печатают, какой роли
не хватает. Бросать исключение нельзя: из-за одной иконки упало бы всё
приложение.

**Иконка по роли в Web Components — рисунок внутри корня.** В остальных
адаптерах корень Icon по роли — сам `<svg>`: его строит адаптер (`roleIcon` у
Vue, React, Svelte и Solid, `RoleIconDirective` у Angular), и класс, размер и
ARIA ложатся на него. Атрибут `is` расширяет только элементы
HTML, и `<svg>` элементом soldy не сделать, поэтому иконка Web Components —
`<span is="so-icon" icon="close">`: корень — элемент потребителя, как у всех
элементов Web Components, а роль — свой атрибут элемента (`icon`, свойство
`el.icon`), а не проп ядра, как `so-role-icon` у Angular. По роли шаблон
кладёт в корень `<svg>` с рисунком, растянутый на корень атрибутами `width`
и `height="100%"` и скрытый от скринридера: имя — у корня. Голый `<svg>` с
рисунком роли — там, где иконка не компонент, а рисунок разметки (отметка
CheckBox), и для приложения — даёт `roleIcon(role)` адаптера, рисунок на
готовом `<svg>` — `drawRoleIcon(svg, role)`.

Поэтому размер ступени общий слой тем даёт корню иконки любого тега, а не
только `svg`: корень `.so-icon` — блок (`:where(.so-icon)` в
`src/components/icon.css` пакета `@soldy-ui/theme-base`), как `svg`
библиотеки под сбросом того же слоя (`src/reset.css`), — у строчного `span`
размер не действует вовсе. Так размер берёт и `<Icon>` без тега в любом
адаптере. Размера вложенному `<svg>` (`.so-icon > svg`) не задаёт никто:
рисунок растягивает разметка, и для темы корень `span` — то же, что корень
`svg`; блоком его, как любой `svg` библиотеки, делает сброс. Сторожат
`ui/webc/__tests__/icon.spec.ts`, `playground/vue/browser/webc-icon.spec.ts`
и «корень span» в `playground/vue/browser/icon-size.spec.ts`.

Цвет иконке oren даёт у того же корня: `--so-icon-color: currentColor` в
`:where(.so-icon)` (`icon/_icon.scss`) — иконка в любом месте цвета его
текста, а рисунок в корне `span` наследует переменную корня (как устроен цвет
— «Цвет иконки — лестница» ниже). Без правила иконка — цвета пакета: у
Material `#1f1f1f` в обеих схемах, и стрелка Select на тёмном поле тёмной
схемы едва виднелась бы. Сторожит `playground/vue/browser/icon-color.spec.ts`.

**Пакетов два, роли у них одни**: `@soldy-ui/icons-material`
(`packages/icons/material/`) и `@soldy-ui/icons-lucide`
(`packages/icons/lucide/`). Приложение подключает один из них. Пакет несёт
только роли `ICON_ROLES`, а не весь чужой набор: иконки приложения — дело
приложения, реестр примет любую. Новая роль закрывается в обоих пакетах —
conformance в `packages/setup/__tests__/icons.spec.ts` гоняет каждый.

**Устройство пакета**: SVG лежат в `src/*.svg` и правятся глазами,
`src/index.ts` **генерируется** своим генератором пакета
(`scripts/generate.mjs`) и закоммичен — как метаданные Angular. После правки
SVG или генератора нужен `npm run generate --workspace=<пакет>`. Забытый
перезапуск ловит CI: шаг «Иконки — дрейф сгенерированного списка» запускает
генераторы обоих пакетов и падает, если `src/index.ts` изменился, — вместе со
списком он сверяет и шапку `@license` (см. ниже).

**Цвет иконки — лестница из трёх ступеней** (решение владельца, 2026-10-23),
одна для всех пакетов и любого способа рисования. От слабого к сильному:

1. **цвет, с которым иконка загружена**, — тот, что стоит в SVG пакета:
   заливка `#1f1f1f` у Material, линия `currentColor` у Lucide. Темы нет или
   ей всё равно — иконка такого цвета;
2. **цвет по умолчанию от темы** — «все иконки такого-то цвета» перекрашивает
   любую иконку любого пакета. У oren — цвет текста места (`:where(.so-icon)`,
   выше);
3. **правило темы для места** — сильнее умолчания: отметка CheckBox у oren —
   цветом варианта (иконка слота с классом Icon тоже), звезда Rating — цветом
   своего слоя.

Лестница — каскад одной переменной, `--so-icon-color`. Пакет пишет покраску в
рисунок не значением, а ссылкой на неё с загруженным цветом запасным
значением: корень `<svg>` исходника снимается (его строит адаптер), и
генератор переносит его покраску на группу вокруг рисунка.

```html
<!-- Material -->
<g fill="var(--so-icon-color, #1f1f1f)"><path d="…" /></g>
<!-- Lucide -->
<g fill="none" stroke="var(--so-icon-color, currentColor)" stroke-width="1.5" …>…</g>
```

Ступень 1 — запасное значение `var()`, ступени 2 и 3 разводит обычная
специфичность: умолчание oren нулевое (`:where(.so-icon)`), правило места
сильнее. Тема задаёт цвет, а не `fill` и не `stroke`, и рисует пакет заливкой
(Material) или линией (Lucide), она не знает. Поэтому правил вида
`svg { fill: currentColor }` у oren нет — ни у кнопки, ни у коробки значка
тоста: такое правило заливало и линии, и свой `<svg fill="none"
stroke="currentColor">` в слоте вставал сплошным пятном. Свой `<svg>` в слоте
тема не красит: он рисует себя сам (`currentColor` — цветом текста места), а
цвет темы берёт, если красит себя той же ссылкой, — так же пишется и своя
иконка роли приложения (`useIcons({ close: … })`). Переменную тема ставит
корню иконки, а не всякому `svg`: в Web Components рисунок — `<svg>` внутри
корня `span`, и правило на всякий `svg` сбросило бы под ним правило места,
написанное корню.

Ссылка — **атрибутом представления SVG, а не `style`**, по двум причинам:

- атрибут слабее любого правила CSS, и тема, которой нужно сменить сам способ
  рисования, пишет его правилом фигурам рисунка: пустую звезду Rating в режиме
  принудительных цветов oren рисует контуром
  (`.so-rating__star > svg * { fill: none; stroke: currentColor }`), и контур
  встаёт у обоих пакетов. Тема и здесь не знает, как рисует пакет, — она
  говорит, как рисовать ей. `style` в разметке было бы не перебить ничем,
  кроме `!important`;
- `style` в разметке снимает политика безопасности (CSP) без `'unsafe-inline'`
  для стилей, и иконка теряла бы цвет, а у Lucide — и сам рисунок. Атрибуты
  представления ей не подчиняются.

`var()` в атрибуте представления понимают Chromium, Firefox и WebKit —
проверено на браузерах Playwright 2026-10-23: запасное значение, наследование
переменной, `currentColor` и правило темы поверх атрибута.

Имя — с префиксом `--so-`, как у всех переменных библиотеки (корневой
`AGENTS.md`, «Префикс — только в глобальном пространстве имён»): пишет её
тема, а читает рисунок пакета, и одноимённая переменная приложения у предка
подменила бы цвет темы.

Lucide рисует обводкой, и пакет остаётся линиями. Толщина обводки пакета — 1.5
единицы `viewBox` 24 вместо 2 у Lucide; она стоит в каждом SVG, а файл с другой
генератор не примет. Звезда Rating залита целиком (`fill` на корне её SVG) под
той же обводкой, и силуэт у неё тот же, что у контурной.

Сторожат conformance «вся покраска рисунка» и «атрибутом представления» в
`packages/setup/__tests__/icons.spec.ts` (каждый цвет в рисунке каждого
пакета — `var(--so-icon-color, <цвет пакета>)`, `style` нет),
`playground/vue/browser/icon-color.spec.ts` (три ступени у обоих пакетов в
обеих схемах) и «принудительные цвета» в
`playground/vue/browser/rating.spec.ts` (контур пустой звезды у обоих
пакетов).

**Иконки чужие.** SVG в `src/` Material — Material Symbols от Google, стиль Rounded
(fonts.google.com/icons), под лицензией Apache-2.0; код пакета — MIT. Поэтому
`license` у пакета — `MIT AND Apache-2.0`, текст Apache лежит в
`LICENSE-Apache-2.0` (см. «Версии пакетов»), а README называет источник.
Apache-2.0 требует пометить изменённые файлы: шапку `src/index.ts` — источник,
лицензию и что изменено — пишет генератор, и пометка `@license` доносит её до
`dist/index.js`, где обычный комментарий сборка теряет. Новую иконку берут из
того же набора и того же стиля: шапка, README и `license` говорят только о нём.

SVG в `src/` Lucide — из пакета `lucide-static` (lucide.dev), под ISC; часть
глифов Lucide взяла из Feather под MIT. `license` у пакета — `MIT AND ISC`, а
`LICENSE-ISC` — файл лицензии Lucide целиком, вместе с уведомлением Feather.
Шапку `@license` с источником и изменениями пишет генератор, как у Material.

**Значки вида — контурные** (у Material — Fill 0 того же глифа, у Lucide
контурные все): `error` и значки видов
тоста — `notification`, `info`, `success`, `warning`. Залитый значок у текста
ошибки Field читался сплошным пятном, а в стопке тостов значки стоят рядом, и
залитый среди контурных выглядит чужим, — новый значок вида тоже берут
контурным. Рисунок решает пакет, а не тема: тема значок только красит.
Сторожит группа «вид» в `playground/vue/browser/toasts.spec.ts`: у значка
каждого вида фигура внутри пуста.

**Иконка в компоненте — три независимые вещи.** Не путайте их:

| Что                                | Чем решается                    |
| ---------------------------------- | ------------------------------- |
| откуда берётся иконка по умолчанию | пакет (`useIcons`)              |
| как заменить её в одном месте      | слот (`#close-icon`, `#clear`)  |
| как до неё доходит состояние       | обёртка с `data-*` вокруг слота |

Третье — это то, что Ark UI называет `Indicator`. Отдельным компонентом его не
заводим: потребитель его не адресует, значит по критерию «часть или слот» это
разметка со слотом внутри.

## Оформление: значения объявляет тема (критично)

Какие у кнопки виды и какие варианты цвета, решает дизайн, а не библиотека.
Одной теме нужны пять видов кнопки и один вариант цвета, другой — ни одного
вида. Поэтому набор значений `variant`, `view`, `shape` и `animation` объявляет
пакет темы, а у ядра его нет.

**Критерий.** Свойство принадлежит теме, если значение описывает только вид, а
набор значений — решение дизайна: `variant`, `view` у Button, Tabs, ListBox,
Accordion и Tags, `view` у CheckBox и RadioGroup, `shape` и `animation` у
Skeleton. Свойство принадлежит библиотеке, если значение читают ядро, плагин
или разметка либо смысл у него один в любой теме: `size` (шкалу читает
`shiftSize`), `orientation`, `alignment` и `position` у Tabs, `position` у
Label, `indicator`, `contentFit`, `placement`, `type` у тоста Toasts (значок
вида по нему выбирает разметка). Такие остаются union'ами ядра.
Булев флаг на месте вида — тоже значение темы: `plain` у CheckBox стал `view`,
флаг не давал теме ни добавить второй вид, ни отказаться от первого.

**Реестр вместо union.** На каждое свойство — интерфейс, наследующий
`TThemeRegistry` (`core/src/common/types.ts`), а тип значения — его ключи:

```ts
export interface IButtonViews extends TThemeRegistry {}
export type TButtonView = Extract<keyof IButtonViews, string>
```

Реестры: `IComponentVariants`, `IButtonViews`, `ITabsViews`, `ICheckBoxViews`,
`IRadioGroupViews`, `ISkeletonShapes`, `ISkeletonAnimations`. Тема дополняет
модуль в своём `index.d.ts`:

```ts
declare module '@soldy-ui/core' {
  interface IButtonViews {
    plain: true
  }
}
```

Тема ничего не объявила — тип значения `never`: у простой темы значений просто
нет. Проверка у значений только типовая: в рантайме значение и так уходит в
класс строкой. Пропсы React, Solid и Svelte и шаблоны Vue выводятся из пропсов
ядра и получают имена темы сами.

`view` у ListBox и Accordion — псевдоним `TButtonView`, а не свой реестр:
строку рисует `Button`, и вид списка — это вид его строк. Со своим реестром
проброс `view` в строку нельзя было бы типизировать. Проброс остаётся: это
значение потребителя, а не библиотеки.

У Tags `view` — тоже псевдоним `TButtonView`: пилюля тега — это вид кнопки. Но
в строку вид не пробрасывается, и тегу он не доставляется вовсе. Крестик —
сосед строки, и фон вида обязан покрывать и его, поэтому пилюлю рисует элемент
тега, а тема читает вид с класса набора (`so-tags--view-<v>`). Сторожит
`packages/ui/vue/__tests__/tags-close.spec.ts`,
`describe('вид — у пилюли, а не у строки')`. Вариант набора тегу тоже не
доставляется: тема красит им тег без своего варианта — с класса набора
(`so-tags--variant-<v>`). Но вариант у тега бывает и свой, и его модификатор
перекрывает набор (см. «`size` и `variant` элемента: владельца, кроме варианта
тега»).

**Умолчание — модификатора нет.** Умолчание свойства темы — `undefined`
(третий аргумент `TDefaultValues`), а не `'normal'` и не `'default'`: такое имя
снова было бы известно библиотеке. Блок без модификатора и есть вид по
умолчанию, рисует его тема. Сеттер принимает `undefined`, фасады элементов не
подставляют запасного значения.

**Модификатор — с префиксом:** `--view-<v>`, `--variant-<v>`, `--shape-<v>`,
`--animation-<v>`. Имя выбирает тема, и без префикса оно столкнулось бы с
модификатором библиотеки: `variant="open"` — с `--open` у Select, вид
`vertical` — с ориентацией Tabs. Ставится модификатор через `TClasses.swap` с
префиксом: пустое значение он пропускает, а `swapClass` с шаблонной строкой дал
бы `--variant-undefined`.

**Разметка библиотеки значений темы не передаёт.** Раньше крестик таба
рисовался с `view="plain"`, строка таба — с `view="none"`: это имена oren, и у
темы с другими именами разметка ставила бы модификатор, под который нет CSS.
Такие части тема красит по контексту (`packages/themes/oren/AGENTS.md`).
Плагины библиотеки значений темы не читают. Плагин, данные которого нужны
только CSS тем, — не плагин библиотеки, и ставит его регистрация темы (см.
«Плагины и расширения снаружи»). Данные, нужные любой теме, пишут плагины
раскладки общего слоя тем — `TTabsViewPlugin` (геометрия активного таба),
`TTableHeadPlugin` (высота закреплённой шапки Table) и `TToastsFrontPlugin`
(высота переднего тоста стопки) в `@soldy-ui/theme-base/setup`
(`packages/themes/base/AGENTS.md`, «Плагины раскладки: `setup/`»); данные,
нужные облику одной темы, — плагин в пакете этой темы. Те и другие тема
ставит своим `defineTheme`.

Нельзя:

- добавлять `| string` в реестр или значения в реестры ядра — пропадёт
  проверка;
- отдавать значения темы через `data-*`: модификатор — это класс, а `dataset` —
  состояние;
- заводить рантайм-списки значений в пакете темы: тема отдаёт CSS и
  `index.d.ts`, списки для стенда живут в стенде.

**Чем стережётся.**

- Фикстура `__tests__/theme.d.ts` в `core`, `ui/vue`, `ui/react`, `ui/svelte`,
  `ui/solid`, `ui/webc` и `ui/angular` — реестры с условными именами, которых
  нет в oren. С именами oren фикстура открыла бы их и коду `src` той же

## Движение: один режим на библиотеку (критично)

Движение — смена места, размера, поворота и формы во времени: въезд панели,
ход ручки, бег индикатора, поворот стрелки, переезд карточки таба, — и плавная
прокрутка. Не движение — цвет, прозрачность, тень, `visibility` и `display` и
анимация, которую ведёт прокрутка (`animation-timeline: scroll()`): она идёт
за пальцем. Переход цвета кнопки, проявление окна Dialog и пульсация Skeleton
— не движение.

Раньше каждая анимация решала сама: карточка Tabs `contained`, ход Slider и
листание ленты слушали настройку системы `prefers-reduced-motion`, а полоса
Tabs `line`, выезд Drawer и бег индикаторов — нет. У пользователя, который
выключил в системе эффекты анимации, одни части ехали, другие стояли, и
понять почему было неоткуда.

**Режим один на всю библиотеку:**

- `system` — по умолчанию: как просит система (`prefers-reduced-motion`);
- `full` — движение всегда: приложение решило, что оно ему нужно;
- `reduce` — без движения всегда.

Задаёт его приложение в точке входа, рядом с темой:

```ts
import { useMotion } from '@soldy-ui/plugins'

useMotion('full')
```

Строка, а не `true | false`: булево не называет умолчание. Режима по
компонентам нет: настройка системы одна на пользователя, и у покомпонентного
режима нет потребителя. Свойство компонента, которое выбирает, что
происходит, — не режим движения: `reorderPreview: 'none'` у Table убирает
сдвиг соседей и приземление не как анимацию, а как поведение (соседи стоят,
колонка встаёт на отпускании), и в `head` и `column` движение по-прежнему
решает режим библиотеки (решение владельца, 2026-10-10).

**Источник один — атрибут `data-so-motion` на корне документа** (`full` или
`reduce`; нет атрибута — `system`). Пишет его только `useMotion`
(`packages/plugins/src/motion/`), копии режима в JS нет. Атрибут — контракт с
любой темой: CSS читает его селектором корня, а без него — медиазапрос
системы, поэтому серверная разметка и кадры до старта приложения идут по
системе; свой режим и там приложение ставит атрибутом в шаблоне страницы.
`useMotion` — в `@soldy-ui/plugins`, а не в реестре setup: режим читают
плагины, а `plugins` setup не импортирует; запись атрибута — операция над
DOM.

**В JS режим читается в момент операции.** Плавную прокрутку решает модуль
движения (`smoothScrollBehavior`): листание Scroller и прокрутка ListBox и
Select к элементу — `scrollBehavior: 'smooth'` плавный, только если движение
не убрано. Подписки на смену режима нет: CSS видит атрибут сам, а прокрутка
спрашивает режим, когда прокручивает. Свой опрос `matchMedia` у плагина,
литерал `'smooth'` и `.animate()` вне модуля — нарушение: до такого плагина
режим приложения не дошёл бы.

**В теме покой — база, движение — надстройка.** Тема oren пишет любое
движение одним миксином (`packages/themes/oren/AGENTS.md`, «Движение —
надстройка»): без него значение встаёт сразу, слой проявляется и гаснет на
месте. Чем заменить движение, которое несёт смысл, решает тема: у oren
неизвестная доля индикаторов без движения — медленное мерцание всей дорожки и
всего кольца (стоящий отрезок читается зависшим, полное кольцо — готовым),
Drawer проявляется и гаснет на месте, `wave` у Skeleton пульсирует, как
`pulse`.

**Код, который ждёт движение темы, завершается и без него.** Замок прокрутки
ждёт конца переходов корня, снятие отбора Select — переходов панели,
перестановка колонки Table — переходов отпущенного заголовка, который едет на
место, а удаление закрытого тоста — переходов его корня
(`plugins/src/utils/afterTransitions.ts`); признак переезда полосы и
карточки активного таба — переходов псевдоэлементов списка
(`themes/base/setup/plugins/transitions.ts`): без переходов все пять
кончаются тем же кадром. Поэтому у того, чьи переходы ждут, нет переходов,
которые идут без движения: у взятого заголовка Table нет и перехода цвета —
переход наведения, начатый отпусканием, задержал бы колонку и без движения.
