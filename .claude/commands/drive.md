Доведи задачу до конца в этом чате: смотри её статус, запускай нужную роль,
снова смотри статус — пока задача не дойдёт до точки, где нужен владелец. Сам
код не читай и не правь: главная сессия должна оставаться лёгкой, всю работу
делают роли.

ID задачи: `$ARGUMENTS`

## Замки

Параллельно могут идти несколько `/drive` в разных чатах. Задачи и папки они
делят атомарными замками — каталогами в общем `.git` основного репозитория
(`git rev-parse --git-common-dir`, дальше `<git>`):

- `<git>/agent-locks/task-<task_id>` — задача занята этим прогоном;
- `<git>/agent-locks/<папка>` — папка пула занята, внутри файл `task` с ID.

Занять — `mkdir` (без `-p`). Получилось — замок твой; ошибка «уже существует»
— занято другим прогоном. Тег `on` в ClickUp медленный и атомарности не даёт,
поэтому решает только `mkdir`. Каждый замок, который взял, сними (`rmdir` после
удаления файла `task`) при любой остановке — кроме сбоя, о котором докладываешь
(тогда замок остаётся, а владелец снимет его `/unlock`).

## Шаг 1. Задача

- **ID дан** — `mkdir <git>/agent-locks/task-<id>`. Занято — остановись:
  задачу ведёт другой чат.
- **ID не дан** — `clickup_list_by_status` со статусом `planning`. Иди по
  очереди как есть (она отсортирована по приоритету), пропуская `busy: true` и
  `blocked: true`, и пробуй `mkdir task-<id>` для каждой. Первая, на которой
  `mkdir` удался, — твоя. Ни одной — скажи и остановись.

Одной строкой: какую задачу берёшь, её статус и приоритет.

## Шаг 2. Цикл

1. `clickup_get_task` — статус и тег `on`.
2. Статус → действие:

   | Статус      | Действие                                |
   | ----------- | --------------------------------------- |
   | ANALYSIS    | роль `analyst`                          |
   | PLANNING    | роль `techlead`                         |
   | DESIGN      | роль `designer` — в папке пула (шаг 3)  |
   | IN PROGRESS | роль `developer` — в папке пула (шаг 3) |
   | APPROVED    | **стоп**: работа сделана, PR ждёт мержа |
   | OVERVIEW    | **стоп**: вопрос к владельцу            |
   | другой      | **стоп**: не знаю, что с ним делать     |

   На задаче висит `on`, а статус рабочий — её держит роль из другого чата
   (или зависший заход): **стоп**, доклад.

3. Запусти роль и передай ей ID задачи; роли, которой нужна папка, — ещё
   строку `Рабочая папка: <абсолютный путь>`. Больше ничего не передавай:
   план и ленту роль читает сама.
4. Роль вернулась — снова `clickup_get_task`. Статус не сменился —
   **стоп**: роль упёрлась (её отчёт — в доклад). Сменился — одной строкой
   «роль → новый статус» и снова пункт 1.

## Шаг 3. Папка пула (дизайнер и программист)

Пул — каталоги `soldy-*` рядом с основным репозиторием, которые
`git worktree list` называет worktree. Основную папку роль не получает: она
держит `main`.

Папку берёшь один раз на прогон и держишь до остановки:

1. Сначала папка, где уже стоит ветка задачи (`task/<id>-*` в
   `git worktree list`), — её и пробуй занять.
2. Иначе — каждую папку пула по порядку: `mkdir <git>/agent-locks/<папка>`.
   Занял — запиши ID задачи в файл `task` внутри замка.
3. Занятая папка должна быть чистой (`git -C <папка> status --short` пуст).
   Грязная — сними её замок, **стоп** и доклад: это брошенная работа, её
   разбирает владелец.
4. Подготовь: `git -C <папка> fetch origin`; запомни `HEAD`; если ветка
   `task/<id>-*` есть — `git -C <папка> switch <ветка>`, иначе
   `git -C <папка> switch --detach origin/main` (ветку создаст роль). Если
   `package-lock.json` между прежним и новым `HEAD` изменился —
   `npm install --no-audit --no-fund` в этой папке.
5. Свободных нет — **стоп**: «все папки пула заняты».

## Остановка

Сними свои замки (папки и задачи) — кроме сбоя, и доложи коротко:

- ID, название, где задача сейчас и почему стоп;
- какие роли отработали и в какой статус перевели;
- APPROVED — ссылка на PR и итог тестов из отчёта программиста; тесты
  красные — сказать первым;
- OVERVIEW — что нужно решить владельцу (из последнего комментария роли);
- в какой папке пула осталась ветка задачи.
