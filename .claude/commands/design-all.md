Прогони дизайнера по всем свободным задачам в `design` — **по одной,
подряд**, в одном рабочем дереве. Каждую задачу ведёт отдельный запуск агента
`designer`: у каждого свой контекст, и падение одного не теряет остальные.

## Перед прогоном

- `gh auth status` — без `gh` дизайнер не откроет PR. Не авторизован —
  остановись.
- `git status` и текущая ветка:
  - дерево чистое — начинай;
  - дерево грязное **на ветке задачи** (`task/<task_id>-*`) — это незаконченный
    прошлый заход. Если эта задача в `design` и свободна, возьми её
    **первой**, вне очереди, и скажи мне, что это продолжение. Иначе —
    остановись;
  - дерево грязное **вне** ветки задачи — остановись: дизайнер не должен
    коммитить чужие изменения.

## Цикл

1. `clickup_list_by_status` со статусом `design` — **заново перед каждой
   задачей**.
2. Возьми первую задачу с `busy: false`, `blocked: false`, которую в этом
   прогоне ещё не брал. Очередь уже отсортирована — не пересортировывай.
   Таких нет — переходи к итогу.
3. Одной строкой скажи мне, какую задачу берёшь и с каким приоритетом.
4. Запусти `designer` и передай ему только ID задачи.
5. Проверь заход. **Любой пункт не прошёл — останови прогон** и скажи мне,
   что именно:
   - `git status --short` пуст. Грязное дерево значит, что заход оборвался:
     дизайнер обязан закоммитить и запушить даже незаконченную работу;
   - `clickup_get_task` — задача ушла из `design` и `on` на ней снят.
     Иначе дизайнер не дошёл до `handoff`;
   - задача в APPROVED — у ветки открыт PR (`gh pr list --head <ветка>`).
     В PLANNING PR не нужен: его откроет программист, когда допишет разметку.

6. Вернись на `main`: `git switch main && git pull --ff-only`. Не вышло —
   останови прогон.
7. Одной строкой: ID, статус, PR, прогон. Дальше — шаг 1.

## Итог

Если хоть у одной задачи прогон красный — скажи об этом **первым делом**.

Таблица по задачам: ID, название, приоритет, куда ушла (APPROVED или
PLANNING), ветка, PR, итог прогона.

Под таблицей:

- по каждой задаче — выжимка спецификации: структура, состояния, иконки,
  цвета; файлы template нового компонента, если рисовал; что дизайнер заметил
  на скриншотах;
- по задачам в PLANNING — что осталось тимлиду;
- что осталось в очереди: занятые — «в работе», заблокированные — «ждёт» и
  кого;
- если прогон остановился — на какой задаче, почему и в каком состоянии
  оставлены дерево и ветка.
