# Таблица на Web Components

Таблица soldy на Web Components рядом с таблицами библиотек на Web Components. Стенд, условия
сравнения и методика — [`README.md`, «Таблица»](README.md#таблица).

## 2026-10-25 — Web Components, первый замер

[869fhddhx](https://app.clickup.com/t/869fhddhx). soldy — `main` на `c3e7d275c`, в условиях
сравнения: `webc:soldy+fit=none+width=3248+track`. 5000 строк × 20 колонок, 3 прогона, медиана;
время — в секундах до успокоения кадров. DOM-узлы — вместе с теневыми деревьями.

```bash
npm run bench -- 5000 3 webc:soldy+fit=none+width=3248+track,webc:carbon,webc:spectrum,webc:vaadin,webc:ui5,webc:plain
```

### soldy ломается на 5000 строках

Таблица soldy на Web Components на 5000 строках не собирается: страница бросает `RangeError:
Maximum call stack size exceeded`, в DOM — 45 тыс. узлов вместо 125 тыс., «выделить все» не
отмечает ни одной строки, сортировка не меняет порядок. На 500 строках таблица работает. Цифр
у soldy поэтому нет.

Стек — рекурсия ожидания подключения (`packages/ui/webc/src/adapter/runtime/waiting.ts`):
закончив подключение, `connecting()` на нулевой глубине разбирает очередь ожидающих элементов,
каждый ожидающий в `_resume` → `connectedCallback` снова зовёт `connecting()`, и тот, закончив,
начинает разбор очереди заново, внутри первого. Глубина стека — число ожидающих элементов, то
есть растёт со строками.

```
RangeError: Maximum call stack size exceeded
    at Array.shift (<anonymous>)
    at drain (waiting.ts)
    at runAll (waiting.ts)
    at connecting (waiting.ts)
    at TElementBase.connectedCallback (element.base.ts)
    at _resume (element.base.ts)
    at runAll (waiting.ts)
    at connecting (waiting.ts)
    …
```

- `fail` — замер участника не уложился в 10 минут (`run.mjs`, потолок участника).
- Строки Carbon, Spectrum и UI5 — разметкой приложения в свете таблицы, как в их документации,
  сверенные по `id`. Carbon сортирует сам (`is-sortable`); Spectrum и UI5 сортировку только
  показывают, строки переставляет приложение — так в их документации.
- Vaadin — без окна (`all-rows-visible`), строки по `itemIdPath`. UI5 — `ui5-table` с
  `ui5-table-selection-multi`; его окно (`TableVirtualizer`) экспериментальное и в замер не шло.
- Carbon сортирует строки посимвольно: первой встаёт «Анна 10156».
- Microsoft FAST и Fluent UI в замере нет: у `data-grid` FAST нет ни сортировки, ни выбора, в
  Fluent UI v3 грида нет. В Shoelace, Web Awesome и Material Web таблицы нет вовсе.

### Вывод

- Таблица soldy на Web Components на больших данных не работает; сравнение с соседями — после
  исправления очереди ожидания.

  в 10 минут не укладываются.
