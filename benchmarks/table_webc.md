### soldy ломается на 5000 строках

Таблица soldy на Web Components на 5000 строках не собирается: страница бросает `RangeError:
Maximum call stack size exceeded`, в DOM — 45 тыс. узлов вместо 125 тыс., «выделить все» не
отмечает ни одной строки, сортировка не меняет порядок. На 500 строках таблица работает. Цифр
у soldy поэтому нет.

Стек — рекурсия ожидания подключения (`packages/ui/webc/src/adapter/runtime/waiting.ts`):
закончив подключение, `connecting()` на нулевой глубине разбирает очередь ожидающих элементов,
каждый ожидающий в `_resume` → `connectedCallback` снова зовёт `connecting()`, и тот, закончив,
начинает разбор очереди заново, внутри первого. Глубина стека — число ожидающих элементов, то
есть растёт со строками.

```
RangeError: Maximum call stack size exceeded
    at Array.shift (<anonymous>)
    at drain (waiting.ts)
    at runAll (waiting.ts)
    at connecting (waiting.ts)
    at TElementBase.connectedCallback (element.base.ts)
    at _resume (element.base.ts)
    at runAll (waiting.ts)
    at connecting (waiting.ts)
    …
```

## 2026-10-25 — Web Components, память строки

[869fmcbwa](https://app.clickup.com/t/869fmcbwa). Почему таблица soldy держит 216 МБ против 70–79 МБ

| ---------------------- | --------- | -------------------------------------------------------------- |
| ядро                   | 12,7      | `TEventEmitter` 5,6 (16 на строку — цена подписок), `TRelays`  |

| плагины                | 1,4       |                                                                |

У React то же снимком — 47,4 КБ на строку: ядро и обмен у него те же цифры, вместо раскладчика —
волокна. Своё у Web Components нашлось в двух местах.

### Исправления

- **Раскладчик атрибутов** (`packages/ui/webc/src/adapter/runtime/paint.ts`) заводится на каждую
  ячейку `td` — ради одного `data-align`. Слои, записанное и сумма были `Map` и объектом на каждое
  имя: около 270 байт на ячейку. Теперь — объекты «имя → значение» и общий пустой набор входов: у
  ячеек с одним набором имён одна форма объекта, около 140 байт. Строка: 6,4 → 3,4 КБ.
- **Сведённое состояние** элемента коллекции (`joinStates`, `runtime/useAdapter.ts`) заводило на
  каждое имя свой геттер — замыкание, его область и пару аксессоров, а сам объект уходил в режим
  словаря. Теперь — `Proxy` с одним обработчиком на все элементы: вид по-прежнему живой, `hasOwn` и
  `Object.keys` те же. Строка: −1,6 КБ.

Куча строки — 43,5 → 39,0 КБ.

## 2026-10-25 — Web Components, обмен setup и эмиттер ядра

[869fmckzg](https://app.clickup.com/t/869fmckzg). Продолжение раздела выше: обмен setup и подписки
ядра — общий слой всех адаптеров, правка в `packages/setup/protected/` с разрешения владельца. soldy
— `main` на `80f66138f` и ветка `task/869fmckzg-exchange-memory`; замеры подряд, в одних условиях.
5000 строк × 20 колонок, 3 прогона, медиана; время — в секундах до успокоения.

```bash
npm run bench -- 5000 3 webc:soldy+fit=none+width=3248+track
npm run heap -- 1000 mounted webc:soldy+fit=none+width=3248+track 0 0 80
```

### Что было в куче

Снимок на 1000 строк, `main` — 38,97 КБ JS-кучи на строку. Обмен setup — около 9,8 КБ:

- **Объект на свойство.** На строку — 46 линий (`TLine`: описание, владелец, имя), 72 ячейки
  (`TCell`) и 26 входов (`TInput`). Подписчиков у ячеек состояния и входов не было: обмен действовал
  по ответу `set()`, ячейка была обёрткой над значением. Описание и имя линии — знание типа, своё у
  монтирования — только владелец.
- **Участники сборки** (`TMember`, 14 на строку) и их списки жили до размонтирования, хотя нужны
  только, чтобы найти таблицу маршрутов и владельцев.
- **Мелкое:** набор классов своих плагинов (`Set`) на каждое монтирование, карта расширений и шина
  у каждого контекста, подписка связки `pluginProps` на набор двумя `on` — карта и два набора.

Подписки ядра (`TEventEmitter`, 5,6 КБ) разобраны по событиям: у 10 из 14,5 эмиттеров строки
(`change` у `TAria`, `TClasses`, `TDataset`, `TAttributes`) слушают одно событие одним обработчиком,
и почти у каждого события обработчик один, а эмиттер заводил под него карту (~100 байт) и набор (~76
байт).

### Исправления

- **Линии — строки таблицы маршрутов** (`TRouting`): одни на поверхность и состав, владельца линия
  берёт из списка монтирования (`exchange.owners`). Состояние (`TStateStore`) и память входов
  (`TInputPort`) — списки значений; объект на вход заводился только ради итерации у Vue, теперь Vue
  читает входы `inputs.pick(props)`. Участников обмен не держит. Строка: 38,97 → 33,20 КБ.
- **Эмиттер:** единственный обработчик события — без набора, набор — со второго; единственное
  событие — в полях эмиттера, карта — со второго. Эмит единственного обработчика повторяет обход
  набора: поставленный за его вызов вызывается в том же эмите (сторож — `event-emitter.spec.ts`,
  новые случаи проходят и на прежнем эмиттере). Строка: 33,20 → 31,73 → 31,01 КБ (набор, затем
  карта).

Обмен setup на строку — около 4,3 КБ из 9,8, эмиттеры — 2,9 из 5,6. Куча строки — 38,97 → 31,01 КБ
(−20%).
