# Серверный рендер

Утечки памяти при серверном рендере: тысячи рендеров страницы со всеми компонентами подряд в
одном процессе Node — и всё ли уходит из памяти после каждого; заодно — не смешиваются ли
соседние запросы на разных языках. Здесь — стенд и методика, общие для журналов платформ рядом
([`vue.md`](vue.md), [`react.md`](react.md), [`svelte.md`](svelte.md), [`solid.md`](solid.md),
[`angular.md`](angular.md)). Как проводилась проверка и её итоги — источник для статьи —
[`report.md`](report.md).

Утечка на сервере опаснее, чем в браузере: вкладку закрывают, а процесс сервера живёт неделями, и
каждый запрос оставляет в нём ещё немного. У Web Components серверного рендера нет — платформ
пять.

## Стенд

[`tools/bench-ssr/`](../../tools/bench-ssr/) — серверная сборка Vite на каждую платформу
(`dist/<платформа>.js`) и прогонщик (`run.mjs`). Страница — все компоненты, которые рисует стенд
разработчика, по одному превью каждого, под одним `LocaleProvider`: превью хостов
(`packages/playground/vue/src/hosts/`) с общими данными (`PREVIEW_PROPS`, `COLLECTION_ITEMS`), те
же, что монтирует замер страниц в браузере ([`pages/`](../pages/README.md)), — поэтому платформы
сравнимы. Select — с опциями данными, как там же. Иконки (`useIcons`) и поведение темы
(`useTheme`) ставятся один раз на процесс, как их ставит приложение.

Рендер в строку — серверным рендерером платформы, на каждый запрос заново, как у сервера:

| Платформа | Рендер                                                                                 |
| --------- | -------------------------------------------------------------------------------------- |
| Vue       | `createSSRApp` + `renderToString` из `vue/server-renderer`                             |
| React     | `renderToString` из `react-dom/server`                                                 |
| Svelte    | `render` из `svelte/server`                                                            |
| Solid     | `renderToString` из `solid-js/web`, сборка `vite-plugin-solid` с `ssr`                 |
| Angular   | `renderApplication`: своя платформа сервера, гидратация, без Zone.js, `provideAttrs()` |

Сборка — продуктовая, всё в бандле, зависимости тоже (`ssr.noExternal`): пакеты Angular выпущены в
частичной форме, и линкер стенда доводит их, только когда их собирает Vite. Angular собирается в
режиме сервера (`ngServerMode`), как его серверный бандл собирает CLI.

```bash
cd tools/bench-ssr
npm run bench                                       # пять платформ, все страницы
npm run bench -- --fw vue,react --renders 1500
node report.mjs                                     # таблицы журнала из results/*.json
```

Флаги: `--fw` — платформы через запятую; `--pages` — страницы (`empty,all,leak`); `--renders` —
рендеров страницы, 3000; `--warm` — из них разогрев, 600; `--every` — замер через столько
рендеров, 150; `--leak-renders` и `--leak-warm` — то же у `leak`, 600 и 150; `--settle` — пауза
перед осевшим замером, мс, 3000; `--dump` — первая разметка каждого языка в
`results/markup/`; `--no-build` — без сборки. Итог — `results/<платформа>.json` (в git не идёт).

## Сценарий

Платформа и страница — свой процесс Node с `--expose-gc`; платформы идут параллельно, страницы
одной платформы — по очереди.

1. **Контрольный рендер** на четвёртом языке (`zhCN`) — до замера: строки языков запросов,
   которые есть в его разметке, — данные страницы (подпись превью), а не перевод, и маркерами
   языка не считаются. Маркеры языка — его строки, которых нет ни у другого языка запросов, ни в
   контрольной разметке.
2. **Рендеры кругами.** Круг — три запроса сразу, по одному на язык (`ruRU`, `enUS`, `arEG`):
   соседние запросы сервера. Рендеры круга запускаются разом (`Promise.all`): асинхронные
   рендереры — Vue и Angular — идут вперемешку на своих ожиданиях, синхронные — друг за другом.
   Между кругами процесс возвращается в цикл событий (`setImmediate`), как сервер между
   запросами: срабатывают таймеры, отпускается то, что держали микрозадачи. Через каждые
   `every` рендеров — замер.
3. **Пауза `settle`** после последнего рендера и осевший замер: таймер превью держит своё до
   срабатывания, и это не утечка.

Страницы: `all` — все компоненты; `empty` — провайдер без компонентов, шум самого замера;
`leak` — `all` с подставной утечкой: на каждый рендер процесс держит экземпляр ядра (`TButton`) и
разметку рендера, как сервер, который складывает ответы в забытый кэш. Прогон, который её не
показал, недействителен — `run.mjs` выходит с ошибкой.

## Методика

- Node 24, продуктовая сборка, `NODE_ENV=production`.
- Замер — после оборота таймеров цикла событий (`setTimeout(0)`: что рендерер отпускает следующей
  задачей, уже отпущено — Solid снимает корень `renderToString` таймером) и двух сборок мусора
  (`gc()`): занятая куча (`process.memoryUsage().heapUsed`) и
  живые экземпляры ядра — компоненты (`TComponent` и наследники, фасады коллекций тоже) и шины
  событий (`TEventEmitter`) — через `queryObjects` из `node:v8`. Он считает и прототипы
  подклассов — около сотни «компонентов» без единого рендера, — поэтому счётчики сверяются с
  замером до первого рендера, а не с нулём.
- **Разметка каждого рендера сверяется с первой разметкой его языка.** У страницы сервера нет
  своего состояния, и разметка, которая разошлась с первой, — это либо язык соседнего запроса,
  либо счётчик, который живёт дольше запроса (id монтирования, растущий на всё время процесса).
  Первые разметки проверяются сами: маркеры своего языка есть, чужих — нет, `lang` у каждого узла
  — свой, ряд частей даты (`so-date-input__segments`) — направления своего языка: `rtl` у
  `ar-EG`, `ltr` у остальных. Текст поля числа — число, и у него `ltr` на любом языке.
- **Рост** — от конца разогрева (`warm` рендеров) до осевшего замера после последнего рендера:
  первые рендеры законно растят кучу — компиляция, кэши форматов локалей, ленивые определения.
- **Итог** страницы: **утечка** — живых экземпляров ядра после паузы больше, чем в конце
  разогрева: страница сервера после рендера не держит ничего, и то, что рендер оставил, копится
  с каждым запросом, — на тысячах рендеров видно и по одному. **Куча растёт** — счётчики на
  месте, а наклон кучи на рендер втрое выше, чем у `empty`, и не меньше 64 Б. Наклон — по Тейлу
  и Сену, медиана наклонов всех пар замеров после разогрева: один замер в стороне от прямой его
  не меняет, а прямая наименьших квадратов от него кренится. Иначе **чисто** (`tools/bench-ssr/verdict.mjs`).
- Время рендера — среднее между замерами, медиана замеров после разогрева. Оно второстепенно:
  платформы гоняются параллельно.
