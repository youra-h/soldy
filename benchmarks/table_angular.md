# Таблица на Angular

Таблица soldy на адаптере Angular рядом с таблицами библиотек Angular. Стенд, условия сравнения
и методика — [`README.md`, «Таблица»](README.md#таблица).

## 2026-10-25 — Angular, первый замер

[869fhddhx](https://app.clickup.com/t/869fhddhx). soldy — `main` на `c3e7d275c`, в условиях
сравнения: `angular:soldy+fit=none+width=3248+track`. Angular 22.2, без Zone.js. 5000 строк × 20
колонок, 3 прогона, медиана; время — в секундах до успокоения кадров.

```bash
npm run bench -- 5000 3 angular:soldy+fit=none+width=3248+track,angular:material,angular:aggrid,angular:prime,angular:zorro,angular:plain,angular:tanstack
```

- Material — `mat-table` по примерам «Table with selection» и «Table with sorting»: `SelectionModel`
  CDK, `MatTableDataSource` и `matSort`. AG Grid — без окна строк и колонок, без предела в 500
  строк, высота по строкам (`domLayout: 'autoHeight'`). PrimeNG — `p-table` с `dataKey`, как
  PrimeVue. NG-ZORRO — `nz-table` без страниц, «выбрать все» — по примеру «Checkbox».
- Первый клик сортировки у Material, AG Grid и PrimeNG ставит первой «Анна 10156», а не «Анна 250»:
  они сравнивают строки посимвольно, без чисел.
- PrimeNG без ключа лицензии пишет в консоль `PrimeUI license is not configured` — как PrimeVue
  на странице Vue; на работу таблицы это не влияет.

### Вывод

- Выделение у soldy — быстрее всех библиотек; рендер на 0,4 с медленнее Material и PrimeNG.
- Память — больше всех: 400 МБ против 104 МБ у Material. У Vue та же таблица — 296 МБ
  (`table_vue.md`): адаптер Angular держит на строку на треть больше.
