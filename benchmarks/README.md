# Замеры производительности

Журналы замеров производительности soldy и сравнения с библиотеками компонентов на разных
фреймворках: сколько стоят рендер, действия и память компонента soldy рядом с тем же
компонентом соседей по экосистеме.

## Журналы

| Журнал                           | Что меряет                                                                                  | Фреймворки | Стенд                                        |
| -------------------------------- | ------------------------------------------------------------------------------------------- | ---------- | -------------------------------------------- |
| [`table.md`](table.md) — базовый | таблица 5000 строк × 20 колонок рядом с таблицами других библиотек: время действий и память | Vue, React | [`tools/bench-table`](../tools/bench-table/) |

Базовый журнал — образец для остальных: на его разделы [«Стенд»](table.md#стенд) и
[«Методика»](table.md#методика) ссылаются новые журналы.

## Как вести журнал

- Журнал дописывается разделами с датой в заголовке (`## 2026-10-09 — Vue, исходная точка`),
  старые разделы не переписываются: так видно, что дала каждая правка.
- Замер на фреймворке, которого в журнале нет, другого компонента или страницы целиком —
  новый файл рядом, а не раздел в старом журнале. Имя файла называет, что меряем
  (`table-angular.md` — таблица на Angular), и файл вносится в список выше.
- У нового журнала свои разделы «Стенд» и «Методика». Что совпадает с базовой методикой,
  даётся ссылкой на [«Методику» `table.md`](table.md#методика), а не копией.

## Что дальше

**Другие фреймворки.** Таблица есть во всех адаптерах, а замерена пока на Vue и React. React в
стенде уже есть: страница `react.html`, рядом с таблицами shadcn/ui, MUI, Ant Design и Mantine
(`table.md`, «React, на равных с shadcn, MUI, Ant Design, Mantine»). Angular (Angular Material,
PrimeNG) и остальные фреймворки — Solid, Svelte, Web Components — пойдут той же методикой, с
таблицами экосистемы фреймворка, но новыми журналами рядом, а не разделами в `table.md`.
