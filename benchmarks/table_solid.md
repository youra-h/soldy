## 2026-10-25 — Solid, состояние без стора и ячейка без `Dynamic`

[869fmcau9](https://app.clickup.com/t/869fmcau9). soldy — ветка `task/869fmcau9-solid-table-memory`
от `main` на `d3519299a`, условия те же: `solid:soldy+fit=none+width=3248+track`, 5000 строк × 20
колонок, 3 прогона, медиана.

```bash
npm run bench -- 5000 5 solid:soldy+fit=none+width=3248+track
npm run heap -- 500 mounted solid:soldy+fit=none+width=3248+track 0
```

Причины — по снимку кучи на 500 строк (`heap.mjs`, режим `mounted`) и профилю CPU рендера.

- **Состояние связки было глубоким стором Solid.** `createStore` оборачивает каждый вложенный
  объект в прокси и заводит сигнал на каждое прочитанное свойство: `cells` строки, каждую
  ячейку, её `aria` и `dataset`. На строку — 480 сигналов, около 24 на ячейку, и 258 КБ JS-кучи.
  Пользы от этого нет: ядро отдаёт значения, сменившееся приходит новым объектом. Состояние
  стало неглубоким — сигнал на свойство, значение как есть (`createShallowState`, как
  `shallowRef` у Vue): 83 сигнала и 148 КБ на строку.
- **Ячейка рисовалась `Dynamic` поверх `mergeProps` трёх наборов.** На ячейку — прокси
  `mergeProps` и `splitProps`, два мемо `Dynamic` и три эффекта `spread`: 690 мс из 1265 мс
  JS-сборки строк. Тег ячейки теперь выбирает ветка, `rowHeader` входит в ключ петли, наборы —
  одним `createPartProps`: 104 КБ на строку.

`trackBy` работает и до правок: после замены данных все 500 `tr` и 10 тыс. ячеек — прежние
узлы, у Vue так же. Замена была медленной от цены обновления ячейки, а не от пересборки строк.

### Вывод

- Память — в 2,5 раза меньше, рендер и замена — почти как у Vue. Сторожат «состояние связки» в
  `ui/solid/__tests__/adapter.spec.tsx` и «rowHeader колонки сменился» в
  `ui/solid/__tests__/table.spec.tsx`.

  эффекты `spread`, прокси `mergeProps`, вставка текста, — и чекбокс строки (254 мс рендера).
  Отдельная задача.

## 2026-10-25 — Solid, корень без `Dynamic`, ячейки строки одним мемо

[869fmcmb7](https://app.clickup.com/t/869fmcmb7). Правка адаптерного слоя Solid. soldy — `main` на
`65656dd17` и ветка `task/869fmcmb7-solid-table-cells`; замеры подряд, в одних условиях:
`solid:soldy+fit=none+width=3248+track`, 5000 строк × 20 колонок, 5 прогонов, медиана; время — в
секундах до успокоения.

```bash
npm run bench -- 5000 5 solid:soldy+fit=none+width=3248+track
npm run heap -- 500 mounted solid:soldy+fit=none+width=3248+track 0
npm run heap -- 500 mounted solid:soldy+fit=none+width=3248+track+mode=none 0
```

Причины — по снимку кучи на 500 строк. На строку у `main` — 95 КБ JS-кучи, 140 вычислений Solid
и 83 сигнала, у Vue — 54 КБ. Вычисление Solid — объект с массивами источников и наблюдателей,
сигнал — объект, его сеттер и привязанный геттер; массивы и области замыканий давали больше
половины кучи строки. Чекбокс строки, когда ячейки уже облегчили, стоил Solid 23 КБ, Vue — 18 КБ
(разница с колонкой выбора и без неё, `mode=none`).

- **Ячейка — корень петли, сигнал записи, прокси `mergeProps` и три эффекта.** Спред на ячейке
  заводил эффект `ref`, которого у ячейки нет, и эффект атрибутов, вставка текста — ещё эффект, а
  петля (`KeyedFor`) — корень и сигнал записи. Ячейки строки без слота рисует теперь одно мемо на
  строку (`createPartNodes`): узел на ключ, проход по ячейкам пишет каждой атрибуты и текст —
  разницу с записанным (`assign`, `insert` из `solid-js/web`). Вычислений на ячейку нет. Ячейка со
  слотом осталась на `KeyedFor`, её узел — `createPartNode`: эффект атрибутов и вставка слота.
- **Корень компонента — `Dynamic`.** На корень — прокси `mergeProps` и `splitProps`, два мемо и три
  эффекта спреда. `Root` адаптера — мемо тега, эффект атрибутов и вставка детей, `ref` — под мемо
  тега. Корни всех компонентов Solid — на нём; на строку таблицы их два — строка и чекбокс.
- **Поле флажка — спред трёх наборов, эффект детей у `<input>` и эффект `indeterminate`.** Теперь
  одним эффектом (`createPartNode`); ячейка выбора строки — так же.
- **Сигнал — на каждое свойство связки.** Подписка отдаёт значение каждого свойства, и сигнал
  заводился на каждое, а разметка читает меньше половины. Теперь сигнал заводит первое чтение. Вид
  двух состояний (`joinState`) читал каждое свойство строки и у фасада и заводил там сигнал — девять
  на строку под свойства раскладки корня; свойство, которого у фасада нет, он читает теперь снизу.
- **Петля и `Root` отдают своё мемо, а не фрагмент над ним:** фрагмент — ещё мемо.

| JS-куча на строку, 500 строк                      | КБ       |
| ------------------------------------------------- | -------- |
| `main`                                            | 94,9     |
| + сигнал по первому чтению                        | 92,6     |
