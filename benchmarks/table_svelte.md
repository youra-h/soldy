### Что держала строка

Снимок кучи на 500 строк (`npm run heap -- 500 mounted svelte:soldy+fit=none+width=3248+track
0`), JS на строку:

| Шаг                                                           | КБ на строку |
| ------------------------------------------------------------- | ------------ |
| `main`                                                        | 185          |
| состояние связки — сырые руны, а не глубокая `$state`         | 125          |
| ветка «слот или текст» — одна на строку, а не в каждой ячейке | 112          |
| проба: ячейка всегда `td`, без `<svelte:element>` (не правка) | 90           |

- **Глубокая руна.** `useExchange` держал состояние связки в `$state(values)`, и Svelte
  оборачивал в прокси всё составное, что отдаёт ядро: массив ячеек строки, каждую ячейку, её
  `aria` и `dataset`, — около 78 прокси на строку, у каждого 8 замыканий-ловушек, `Map`
  источников и источник на прочитанный ключ. Ядро отдаёт значения, а не ручки (AGENTS.md,
  «Контракт границы core → ui»), следить внутри них незачем — у Vue то же решено `shallowRef`
  (`table.md`, 869fekb4g). Теперь у каждого свойства своя сырая руна (`$state.raw`).
- **Ветка слота в ячейке.** `{#if props.cell}` стоял в каждой ячейке — блок Svelte с эффектами
  на ячейку. Ветка вынесена из петли: одна на строку.
- **`<svelte:element>` ячейки** (`th` у заголовка строки, иначе `td`) стоит ещё ~20 КБ на
  строку, но `{#if}` с `th`/`td` экономит из них лишь 2 КБ ценой четырёх копий разметки
  ячейки. Тег выбирается в каждой ячейке, и дешевле способа у Svelte нет — оставлен.
- **Страница стенда.** Строки страницы Svelte лежали в глубокой `$state` (`page.svelte.ts`), и
  каждая запись была прокси — за это платил каждый участник. Теперь руна сырая, как
  `shallowRef` у страницы Vue: голый Svelte — 88 МБ вместо 107.

### Что держала строка

Снимок кучи на 500 строк, JS на строку:

| Шаг                                                                  | КБ на строку |
| -------------------------------------------------------------------- | ------------ |
| `main`                                                               | 101,9        |
| ветка `th`/`td` — на серию ячеек с тем же `rowHeader`, а не в ячейке | 84,0         |
| состояние связки — прокси над рунами, а не геттер на свойство        | 78,9         |
| вид двух состояний (`joinState`) — прокси, а не геттер на имя        | **77,3**     |
| Vue (`table_solid.md`, те же флаги)                                  | 53,7         |

- **Ветка тега в ячейке.** `<svelte:element>` (`th` у заголовка строки, иначе `td`) — блок Svelte:
  менеджер веток (три `Map` и `Set`, два замыкания), эффекты блока и ветки, якорь-комментарий и
  текстовый якорь внутри элемента, — на каждую ячейку. Ветка теперь над петлёй: одна на серию
  подряд идущих ячеек с тем же `rowHeader` (`runsOf`, как пайп `soRuns` у Angular), ячейка —
  статический `td` или `th`. Менеджеров веток на строку — 13,7 вместо 32,7, эффектов — 117 вместо
  173, текстовых узлов — 36 вместо 74. В прошлом заходе ветку `{#if}` с `th`/`td` в каждой ячейке
  отвергли: она стоила почти столько же, сколько `<svelte:element>`, — дело было в ветке на ячейку,
  а не в её виде.
- **Состояние связки.** На каждое свойство стояли руна в обёртке, геттер-замыкание с двумя
  областями и пара аксессоров на объекте состояния, у элемента коллекции — ещё геттер на имя в
  виде двух состояний. Теперь руны лежат в `Map`, а читает их одно прокси на связку с общим
  обработчиком; вид двух состояний — тоже прокси. Заводить руну первым чтением, как сигнал у Solid,
  Svelte не даёт: руна, заведённая в исполняемом эффекте, в нём же не отслеживается.
