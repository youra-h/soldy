# Отклик на действие

Что чувствует пользователь на странице, где компонентов много: сколько проходит от его действия до
кадра, где оно отрисовано, — у полной скорости и с процессором, замедленным в 4 и 6 раз, как на
среднем телефоне, — и не делает ли фреймворк лишней работы: перерисовывает ли действие на одной
копии остальные 49. Замер страниц ([`pages/`](../pages/README.md)) мерит вес и монтирование, а
этот — отклик. Здесь — стенд и методика, общие для журналов платформ рядом ([`vue.md`](vue.md),
[`react.md`](react.md), [`svelte.md`](svelte.md), [`solid.md`](solid.md), [`webc.md`](webc.md),
[`angular.md`](angular.md)). Итоги на всех платформах — источник для статьи — [`report.md`](report.md).

## Стенд

[`tools/bench-pages/`](../../tools/bench-pages/) — та же страница, что у замера страниц
(`index.html?fw=<фреймворк>`): хосты превью стенда разработчика, одни данные на все платформы,
страница компонента — N копий его превью под одним корнем и одним `LocaleProvider`. Прогонщик —
`interaction.mjs`, таблицы журнала — `interaction-report.mjs`.

```bash
cd tools/bench-pages
npm run interaction                                             # сборки, все платформы, таблицы
node interaction.mjs --fw vue,react --pages select,tabs --rates 1,6
node interaction-report.mjs react                               # таблицы из results/interaction-react.json
```

Флаги: `--fw` — платформы через запятую; `--pages` — страницы (без него — все из `ACTIONS`);
`--n` — копий на странице, 50; `--rates` — замедления процессора, `1,4,6`; `--warm` — кругов
разогрева на каждое замедление, 2; `--reps` — кругов замера, 10; `--count-reps` — кругов счёта
перерисовок, 3; `--no-count` — без счёта; `--no-build` — без сборок. Итог —
`results/interaction-<платформа>.json` (в git не идёт).

## Действия

На странице из 50 копий действие идёт на первой — настоящим вводом Playwright (`locator.click`,
`keyboard.press`, `keyboard.type`), а не событиями из скрипта страницы: меряется путь браузера
целиком, от события ввода до кадра. Круг страницы — её действия по порядку:

| Страница       | Действия                                                                        |
| -------------- | ------------------------------------------------------------------------------- |
| `select`       | открыть стрелкой и закрыть Escape; символ в поле (`editable`: панель с отбором) |
| `menu`         | открыть кнопкой и закрыть Escape                                                |
| `date-picker`  | открыть кнопкой и закрыть Escape; язык страницы `ruRU` и обратно `enUS`         |
| `dialog`       | открыть кнопкой и закрыть Escape                                                |
| `input`        | символ в поле                                                                   |
| `tabs`         | клик по второму табу и по первому                                               |
| `calendar`     | язык страницы туда и обратно — 50 видимых месяцев                               |
| `number-input` | язык страницы туда и обратно                                                    |

Перед действием, вне замера, прогонщик ставит то, что ему нужно: закрывает панели, оставленные
прошлым действием, ставит фокус в поле. После — сверяет, что действие сделало своё: после открытия
одна открытая панель, после закрытия ни одной (`data-open` слоя); сбой попадает в журнал. Язык
страницы меняется из скрипта (`bench.switchLocale`) — переключателя языка на странице нет, — и его
время идёт от вызова.

## Методика

- Продакшн-сборка, Chromium (Playwright), окно 1600×1000; платформы — по очереди, своим браузером
  каждая: параллельные браузеры замедляли бы друг друга.
- Замедление — `Emulation.setCPUThrottlingRate` протоколом DevTools, на время замеров страницы;
  монтирование идёт на полной скорости.
- **Кадр** — от первого события ввода действия (`event.timeStamp` первого `pointerdown`,
  `keydown`, `beforeinput`…) до конца кадра после последнего (`click` у нажатия, `keydown` у
  клавиши, `input` у набора): `requestAnimationFrame` и задача после него, как у стенда таблиц.
- **Успокоение** — до трёх кадров подряд чаще, чем раз в 50 мс: страница перестала занимать поток.
- **INP** — что браузер сам считает откликом действия (Event Timing, самое долгое из его событий:
  от ввода до кадра после обработчиков). Короче 16 мс браузер не сообщает — «<16».
- Медиана из `reps` кругов после `warm` разогрева, на каждом замедлении.

### Перерисовки

Второй проход — счётная сборка (`vite build --mode count`, `dist-count`): та же продакшн-сборка, где
фреймворк считает свою работу. Действия те же, на полной скорости, на странице из 50 копий и на
странице из одной: работа, которой на странице из 50 больше, — работа для соседей.

| Платформа      | Что считается                                                                                       |
| -------------- | --------------------------------------------------------------------------------------------------- |
| Vue            | рендер компонента — его функция `render` после монтирования (хук devtools, `__VUE_PROD_DEVTOOLS__`) |
| React          | компонент, который React отрисовал в коммите (хук devtools, флаг `PerformedWork`)                   |
| Svelte         | прогон эффекта шаблона (`template_effect`, `attribute_effect`)                                      |
| Solid          | прогон эффекта отрисовки (`createRenderEffect` — вставки, атрибуты, спреды)                         |
| Angular        | проход шаблона компонента (`ɵɵdefineComponent`) и такт обнаружения изменений                        |
| Web Components | фреймворка нет — только записи в DOM                                                                |

У всех платформ ещё и записи в DOM (`MutationObserver`) по месту: в копии, на которой действие, в
остальных копиях и вне страницы (слой в конце `body`). Счётчики — обёртки рантайма
(`tools/bench-pages/count/`): Svelte, Solid и Angular подменяются алиасом сборки на модуль, который
отдаёт всё как есть и считает свою функцию; Vue и React сообщают в хуки devtools, которые ставит
`count/probes.ts` до загрузки фреймворка. Имена — у компонентов Vue, React и Angular (счётная
сборка без минификации): журнал называет, кто перерисовался.

Счёт у фреймворков разный по смыслу — компонент у Vue и React, эффект у Svelte и Solid, шаблон у
Angular, — и сравнивать его между платформами нельзя. Сравнивается он внутри платформы: 50 копий
против одной и до правки против после.
