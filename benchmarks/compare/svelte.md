# Соседи — Svelte

Стенд, условия, сценарии и метрики — [`README.md`](README.md). Здесь — участники Svelte, матрица и
прогоны.

## 2026-10-26 — первый прогон

### Участники

| Участник | Пакет и версия                                | Как подключён                                                                                                                                 |
| -------- | --------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| soldy    | `@soldy-ui/svelte` исходниками, Svelte 5.57.2 | тема oren с поведением (`useTheme`), иконки Material, `LocaleProvider` с `enUS` — как хост стенда разработчика                                |
| carbon   | `carbon-components-svelte` 0.113.1            | тема по умолчанию `white` (`css/white.css`), провайдера нет; компоненты в синтаксисе Svelte 4, Svelte 5 компилирует их в режиме совместимости |
| bits     | `bits-ui` 2.20.2                              | headless, без стилей и без провайдера в корне                                                                                                 |

**Bits — без оформления shadcn-svelte.** shadcn-svelte не пакет: он копирует компоненты в
приложение с классами Tailwind поверх Bits. Стенд берёт Bits как есть — без классов и Tailwind, как
стенд таблицы (`tools/bench-table/libs/svelte/shadcn.svelte`): мерится работа компонентов, а не
CSS. Поэтому размер bits — нижняя граница для приложения на shadcn-svelte, а вес копии — почти
честный (классы Tailwind — строки атрибутов).

Страница — `libs/svelte/<участник>/<компонент>.svelte`, `libs/svelte/mount.ts` монтирует N копий
одним корнем Svelte (`mount` + `flushSync`) внутри `Root` из `setup` участника, если он есть
(у soldy — `LocaleProvider`), — как хост soldy.

### Матрица

| Страница    | carbon                                                                                                                           | bits                                                                                                                         |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| button      | `Button`                                                                                                                         | `Button.Root`                                                                                                                |
| input       | `TextInput`                                                                                                                      | — нет компонента (поле shadcn-svelte — нативный `<input>` с классами)                                                        |
| check-box   | `Checkbox` с `labelText`                                                                                                         | `Checkbox.Root` + `Label.Root` по `for`                                                                                      |
| switch      | `Toggle` с `labelText`                                                                                                           | `Switch.Root` + `Label.Root` по `for`                                                                                        |
| select      | `ComboBox`; фильтр — `shouldFilterItem` по документации (по умолчанию не фильтрует)                                              | `Combobox`; фильтр по введённому тексту — приложением, как в документации                                                    |
| tabs        | `Tabs` + `TabContent`                                                                                                            | `Tabs` с `Content` на каждый таб                                                                                             |
| dialog      | `Modal` с `TextInput` внутри                                                                                                     | `Dialog`, поле — нативный `<input>`                                                                                          |
| tooltip     | `TooltipDefinition` ¹                                                                                                            | `Tooltip` с `Provider` на копию, задержка 400 мс ²                                                                           |
| menu        | `MenuButton`: группа флажков, группа переключателей, сочетания (`shortcutText`), подменю с подменю, выключенный, `kind="danger"` | `DropdownMenu`: `CheckboxGroup`, `RadioGroup`, `Sub` в `Sub`, выключенный; сочетания и вид «опасного» — разметкой приложения |
| date-picker | `DatePicker` + `DatePickerInput` (flatpickr)                                                                                     | `DatePicker`: поле сегментами, кнопка и календарь в панели — сборка из документации                                          |

Сверено: те же тексты и пять элементов `COLLECTION_ITEMS`; пункт меню soldy с календарём в
панели (`Menu.PopoverItem`) у соседей не собран — как у соседей React.

¹ Подсказки вокруг произвольного триггера в Carbon Svelte нет (`Tooltip` несёт свою иконку);
`TooltipDefinition` — кнопка, открытие наведением (с задержкой 100 мс) и фокусом — ближе всего к
превью soldy. Наведение сценарий шлёт её обёртке (`mouseenter`), на ней слушатель.

² У Bits задержка по умолчанию 700 мс, а шаг наведения ждёт 450 мс; задержка — как у soldy (400).
Провайдер принадлежит корню приложения, но обёрнут вокруг каждой копии, чтобы его не несли
остальные страницы.

Каждый сценарий проверен пробой в браузере: панели открываются и закрываются, флажок меню, выбор
опции и дня, переключение табов меняют состояние, подменю раскрываются до второго уровня. Число
действий совпало на всех страницах (расхождений прогонщик не напечатал).

Особенности сценариев:

- **bits** — нажатие своим помощником `click`: та же цепочка указателя, что у `press`, но клик с
  `detail: 1`, как от мыши. `element.click()` общего `press` даёт `detail: 0` — клик клавиатуры или
  экранного диктора, — и триггеры Bits, которые открываются на `pointerdown` (меню, комбобокс),
  считают его вторым переключением (обработка VoiceOver) и сразу закрываются.
- **carbon, bits** — меню закрывается выбором флажка (поведение обеих библиотек); Escape после него
  уходит в закрытую панель, но шаг засчитан, как у soldy.

### Наблюдения

Что можно утверждать:

- **Утечек нет ни у кого.** У soldy все страницы чистые; у соседей «куча растёт» на select, tabs,
  menu, date-picker и др. (наклон до 37 КБ/цикл у date-picker bits), но осевших узлов и
  слушателей нет — это рост кучи, а не удержание снятого. Отрицательные узлы и слушатели у select
  carbon — счётчики падают, не растут.
- **Простые контролы — одного порядка.** button, check-box, switch, input, tooltip: soldy 23–67 КБ
  на копию, carbon 12–29, bits 4–42. Bits легче всех, потому что без стилей и без своих полей.
- **Составные — soldy в разы тяжелее.** select 376 КБ против 52–62, tabs 383 против 109–158,
  dialog 149 против 26–123, menu 1004 против 38–62, date-picker 1046 против 88–108. Порядок тот же,
  что на React и Vue (menu soldy там 597 и 769 КБ), на Svelte — выше всех.
- **Размер: soldy не трясётся.** Каждая страница soldy — 185 КБ gzip, кнопка столько же, сколько
  весь набор (189): точка входа тянет почти всю библиотеку. У соседей кнопка — 22 (bits) и 93
  (carbon, из них основная часть — общий CSS темы), весь набор — 108 и 164.

Чего утверждать нельзя:

- **Монтирование — второстепенно.** Платформы шли параллельно (другие агенты гоняли свои стенды в то
  же время), и миллисекунды soldy (menu 337, date-picker 297) с соседями сравнивать только по
  порядку.
- **Строки `all`** — вес всего набора (по копии каждого компонента): soldy ≈ 3,6 МБ, carbon ≈ 0,7 МБ,
  bits ≈ 0,5 МБ.
- **bits без CSS** — размер и вес bits меньше, чем у приложения на shadcn-svelte.
