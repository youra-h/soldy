# Соседи — отчёт для статьи

Первый прогон 2026-10-26: soldy рядом с 17 библиотеками на шести платформах. Стенд, условия и
методика — [`README.md`](README.md); цифры, матрицы и сноски — журналы платформ.

## Как проверяли

- Одна страница — 50 копий компонента одним корнем фреймворка, 2 цикла разогрева и 20 циклов
  замера: смонтировать, сценарий на 10 копиях, снять. Куча, узлы и слушатели — после сборки
  мусора протоколом DevTools.
- Десять общих компонентов: button, input, check-box, switch, select с вводом, tabs, dialog с полем,
  tooltip, menu с подменю, date-picker. Данные и тексты — те же, что у превью soldy. Сценарии —
  те же действия на разметке соседа, число действий у пары совпало на всех страницах всех
  платформ.
- Размер — продакшн-сборка, точка входа на страницу, gzip и brotli JS + CSS.

## Итоги

**Утечки.** У soldy после снятия не остаётся ничего ни на одной странице ни одной платформы:
узлы, слушатели и экземпляры ядра на месте, куча не растёт. У соседей найдены утечки: Kobalte
Combobox (8 узлов на копию за цикл), UI5 ComboBox (сотни узлов и слушателей на копию), Vuetify
(слушатели плагина на каждое приложение страницы), Naive UI Checkbox и PrimeVue Select (тысячи
узлов). «Куча растёт» у соседей встречается часто — Ant Design, NG-ZORRO, Vaadin и другие.
Утечки соседей до публикации стоит подтвердить отдельным прогоном.

**Вес простых контролов** (button, input, check-box, switch) — одного порядка с соседями: где
легче, где тяжелее в 2–3 раза.

**Вес составных** (select, tabs, menu, date-picker) у soldy в 3–30 раз выше, чем у соседей, на
всех платформах. Меню и календарь — 430–1000 КБ на копию против десятков у соседей. Часть разницы
— соседи монтируют панели при открытии, а soldy собирает коллекции заранее; порядок разницы этим
не объясняется. Вес набора из всех десяти компонентов: soldy 1,0–3,7 МБ, соседи 0,13–3,1 МБ.
После 869fmhua9 меню и DatePicker тоже строят панель с первого открытия: на Vue меню 733 → 67 КБ,
DatePicker 702 → 149 КБ, на React 567 → 60 и 621 → 126 — меню вровень с соседями, DatePicker —
внутри их диапазона (журналы Vue и React, раздел «панели меню и DatePicker с первого открытия»;
остальные платформы не перемерены). После 869fmj95y так же, с первого открытия, Select строит
опции из данных, а страница soldy `select` получила опции данными, как у соседей: на Vue
232 → 89 КБ на копию при соседях 82–198, на React 212 → 81 при 18–126 — внутри их диапазона
(журналы Vue и React, раздел «опции Select из данных с первого открытия»).

**Проводка адаптеров Angular и Svelte** после 869fmhuak легче: у Angular копия кнопки — 27,4 →
23,8 КБ, меню — 735 → 558, набор — 2,5 → 2,1 МБ; у Svelte — на 1–3 %, кнопка 22,5 → 21,9 КБ
(журналы Angular и Svelte, раздел «проводка адаптера легче»). Классы ядра и `setup` на копию у всех
платформ одни и те же, так что остаток разницы — во фреймворке и в стенде: около 9 КБ копии кнопки
Angular — способ, которым стенд ставит копии (каждая — свой корень `createComponent`), меню Angular
держит все пункты разметки с первой отрисовки, а у Svelte главное — блоки разметки (около 4 КБ на
кнопку). На них заведены задачи 869fmjpha, 869fmjpj2 и 869fmjpg8.

**Копии soldy на Angular** после 869fmjpha — представления одного шаблона, а не свой корень
`createComponent` у каждой: кнопка 23,8 → 13,1 КБ — вровень с NG-ZORRO (12,8), ListBox 258 → 171,
табы 353 → 227; меню не изменилось (557 → 548), его вес — пункты-проекция (журналы Angular, раздел
«копии … — представления одного шаблона»).

**Размер сборки.** В первом прогоне любая страница soldy весила столько же, сколько все десять
компонентов вместе, — 170–305 КБ gzip: пакеты не объявляли `sideEffects`, и сборщик не выбрасывал
неиспользуемое. После объявления (869fmgyhw) страница с одной кнопкой — 67–158 КБ вместе с CSS
темы (35 КБ), в 2–2,5 раза меньше, и на React, Vue, Angular и Svelte она вровень с соседями:
React 116 против 76–112, Vue 100 против 65–125, Angular 158 против 119–225, Svelte 79 против
22–93. На Solid кнопка soldy тяжелее Kobalte (67 против 13): рантайм Solid лёгкий, Kobalte — без
стилей, и вес — сама soldy и тема.
Составные страницы (select, menu, date-picker) — у верхней границы соседей. Web Components тогда
не изменился (~190 КБ на любой странице): импорт пакета определяет все элементы. Со входом на
элемент (869fmj1tw, `import '@soldy-ui/webc/button'`) кнопка — 67 КБ против 23–61 у соседей (JS
32 КБ, как на Solid), select, tabs, dialog, menu и date-picker — 82–131 КБ, внутри диапазона
соседей или у его верхней границы; корень пакета по-прежнему
определяет все элементы, 193 КБ (журнал Web Components, раздел «вход на элемент»). На странице
«все компоненты» soldy вровень с соседями (React 221 КБ против 155–273). Журналы платформ — раздел
«2026-10-26 — размер сборки после `sideEffects`».

**Монтирование** (второстепенно: платформы шли параллельно) — простые страницы вровень, составные
у soldy в 3–5 раз дольше.

## Что можно утверждать

- soldy не течёт там, где течёт часть соседей, — на всех шести платформах одной логикой.
- Простые контролы soldy по весу на уровне популярных библиотек.

## Чего утверждать нельзя

- Размер сборки soldy на Web Components без оговорки о входе: страницы стенда импортируют входы
  элементов, а корень пакета (`import '@soldy-ui/webc'`, путь по умолчанию) — все элементы, 193 КБ
  на любой странице.
- «Легче соседей» на составных компонентах — сейчас наоборот.
- Сравнение с безголовыми библиотеками (Reka, Bits UI, Kobalte) — без оговорки: у них нет стилей,
  у soldy — тема с поведением. shadcn/ui на React собран со своими стилями Tailwind.
- Подсказки: у части соседей сценарий фокусом её не открывает (сноски журналов), и вес под
  сценарием у них меньше.

## Что разобрать

1. Вес составных компонентов: что держит копия меню и календаря soldy.
2. Общие помощники сценариев (`tools/bench-pages/scenarios.ts`): клавиша без `code` и `keyCode`,
   клик с `detail: 0`. Часть соседей их не понимает, и журналы держат местные обходы.
