# Соседи

Страницы компонентов soldy рядом с теми же страницами библиотек соседей: сколько весит копия,
сколько монтируется страница, не течёт ли память и сколько весит сборка. Здесь — стенд, условия
и методика, общие для журналов платформ ([`vue.md`](vue.md), [`react.md`](react.md),
[`angular.md`](angular.md), [`svelte.md`](svelte.md), [`solid.md`](solid.md),
[`webc.md`](webc.md)); отчёт для статьи — [`report.md`](report.md).

Замер страниц самой soldy — [`pages/`](../pages/README.md): его сценарии, методика и итог страницы
здесь те же, а меняется только то, что сравнение с соседями требует.

## Стенд

[`tools/bench-compare/`](../../tools/bench-compare/) — по образцу стенда таблицы: вне workspaces,
зависимости соседей ставятся только в стенд (`npm install` в его папке), фреймворки — тех же
версий, что в корне, одной копией на страницу (`dedupe`), soldy — исходниками.

```bash
cd tools/bench-compare
npm install                                       # один раз: библиотеки соседей
npm run bench -- --fw react                       # soldy и все соседи React
npm run bench -- --fw vue --libs naive --pages select,all --cycles 10
npm run size -- --fw react                        # размер сборки страниц
node report.mjs react                             # таблицы журнала
```

- **soldy** — страница стенда `tools/bench-pages` (хосты превью стенда разработчика), собранная
  прогоном в `dist/<платформа>/soldy`: те же превью и данные (`PREVIEW_PROPS`,
  `COLLECTION_ITEMS`), что в замере страниц.
- **Сосед** — страница `<платформа>.html?lib=<библиотека>`, папка `libs/<платформа>/<библиотека>/`:
  `setup` — провайдер, тема и стили библиотеки, как их ставит приложение; файл на компонент —
  одна копия страницы с теми же данными и текстами, что превью soldy; `scenarios.ts` — сценарии на
  её разметке. `libs/<платформа>/mount` монтирует N копий одним корнем фреймворка, как хост soldy.
- `libs/<платформа>/soldy/` — те же превью soldy файлами, только для размера сборки: хост стенда
  разработчика тянет все превью разом, и дерево сборки по нему не трясётся.
- Флаги прогона те же, что у `tools/bench-pages` (`--n`, `--act`, `--warm`, `--cycles`,
  `--settle`, `--pages`, `--no-build`), и ещё `--libs` — соседи через запятую. Итог —
  `results/<платформа>.json` и `results/size-<платформа>.json` (в git не идут).

## Матрица

Сравниваются только компоненты, которые есть у обоих, с одними данными и теми же возможностями.
Сравниваемые страницы — `button`, `input`, `check-box`, `switch`, `select` (с вводом и поиском),
`tabs`, `dialog` (с полем внутри), `tooltip`, `menu` (группы флажков и переключателей, подменю с
подменю, выключенный пункт), `date-picker` (поле с календарём во всплывающей панели) — список в
`tools/bench-compare/pages.ts`. Нет компонента у соседа — клетка пустая, в зачёт не идёт, и в
`all` этой пары его нет. Чего у соседа нет, но приложение собирает из его же частей так, как
советует его документация (подменю — вложенным меню), собрано так; пометка — в матрице журнала.
Журнал платформы держит матрицу: компонент soldy → компонент соседа и что сверено.

## Сценарии

Те же, что у страниц soldy (`tools/bench-pages/scenarios.ts`), и теми же помощниками — полная
цепочка указателя, `insertText`, клавиши, — только на разметке соседа. Число действий у пары
обязано совпадать: прогонщик сверяет его на каждой странице и печатает расхождение, а журнал такую
клетку не засчитывает. Действие, которое не нашло узла, не считается, — поэтому совпавшее число и
значит, что сценарий прошёл.

Шага языка в цикле нет ни у кого: общего источника языка у соседей нет, и цикл — смонтировать,
сценарий, снять.

## Метрики

- **Вес копии** — куча со страницей минус пустая перед ней, в первом цикле после разогрева, на N.
- **Монтирование** — от вызова монтирования до второго кадра, медиана циклов. Второстепенно:
  платформы и участники могут идти параллельно.
- **Утечки** — осевшие счётчики (куча, узлы, слушатели; экземпляры ядра — только у soldy) и итог
  страницы — по правилам замера страниц ([`pages/README.md`](../pages/README.md), «Методика»):
  утечка, «куча растёт» (наклон втрое выше, чем у `empty` того же участника, и не меньше 4 КБ) или
  чисто.
- **Размер сборки** — продакшн-сборка, точка входа на страницу: `setup` библиотеки и одна копия;
  `all` — все её сравниваемые страницы. Размер точки — её чанк и всё, что он статически
  импортирует, плюс их CSS; gzip (9) и brotli (11), каждый файл сжат отдельно. Шрифты и картинки
  не считаются.

## Условия

Соседи — с настройками по умолчанию, кроме того, без чего сценарий не пройти; тема у каждого —
своя по умолчанию. soldy — тема oren с поведением (`useTheme`) и пакет иконок Material, как в
README пакетов.
