# AGENTS.md — общий слой тем

Инструкции для пакета `@soldy-ui/theme-base`. Здесь — то, что нужно частям
soldy в любой теме, а не облику одной: сброс узлов библиотеки, механизмы, на
которые части опираются, и сторожа, которые проверяют CSS каждой темы
репозитория. Решения одной темы сюда не переносят (корневой `AGENTS.md`,
«Темы: у пакета темы свои инструкции»): палитра, виды и варианты, вид
состояний, движение облика — дело темы. Тема oren описана в
`packages/themes/oren/AGENTS.md`.

## Что здесь чем является

| Файл                            | Роль                                                                                       |
| ------------------------------- | ------------------------------------------------------------------------------------------ |
| `src/index.css`                 | вход: порядок слоёв и импорты частей (см. «Слои»)                                          |
| `src/reset.css`                 | сброс узлов библиотеки, подслой `so.reset` (см. «Сброс узлов библиотеки»)                  |
| `src/direction.css`             | знак направления письма `--so-dir-sign`, слой `so` (см. «Знак направления письма»)         |
| `theme-variables.json`          | контракт: переменные, которые база читает, а задаёт тема (см. «Контракт: переменные темы») |
| `__tests__/base-css.spec.ts`    | свои сторожа базы — по её CSS (см. «Сторожа»)                                              |
| `__tests__/themes.ts`           | темы репозитория и их CSS, собранный в памяти их конфигом                                  |
| остальные `__tests__/*.spec.ts` | сторожа любой темы — по собранному CSS каждой темы (см. «Сторожа»)                         |

```bash
npm run test --workspace=@soldy-ui/theme-base  # сторожа базы и каждой темы
npm run test:theme                             # то же и тесты oren
```

## Чистый CSS, без сборки

База — чистый CSS: без препроцессора и без Tailwind. Тема берёт её как есть,
своим сборщиком, и тема без Tailwind и Sass их директив не развернула бы.
Tailwind бывает только в теме: oren подключает его сама, частями.

Компилировать в пакете нечего, поэтому шага сборки нет: `exports["."]` и
`style` ведут в `src/index.css`, `files` везёт `src` и контракт, скрипта
`build` нет, и в корневом `build` базы нет (`docs/agents/build.md`, «Сборка
пакетов»). Тема вшивает базу в свой CSS, и приложение по-прежнему подключает
один файл темы. Поэтому база у темы — в `devDependencies`, точной версией
группы: потребителю темы ставить её незачем, она уже внутри её `dist`.

## Слои

Правила базы — в слое `so`: имя слоя у документа общее, как имя класса, и
потому с префиксом (корневой `AGENTS.md`, «Префикс — только в глобальном
пространстве имён»). Сброс — подслой `so.reset`. Правила слоя вне его
подслоёв сильнее любого подслоя, поэтому остальные правила базы перекрывают
сброс, не споря с ним специфичностью, а правила темы вне слоёв — всю базу.

Новая часть базы — файл в `src` и строка `@import` в `src/index.css`: в слой
`so`, а если ей место ниже остальных правил базы — в его подслой. Правило вне
слоя `so` встало бы над правилами темы и утилитами приложения, и его роняет
сторож.

**Как тема подключает базу** — импортом по имени пакета, первой в своих
стилях:

```css
/* тема без Tailwind: слой `so` встаёт там, где базу импортировали */
@import '@soldy-ui/theme-base';

/* тема на Tailwind — в его слой `base`, на место preflight (так oren) */
@import '@soldy-ui/theme-base' layer(base);
```

У темы на Tailwind база ложится в слой `base` (`base.so`, `base.so.reset`), и
против утилит Tailwind приложения она стоит там же, где стоял preflight. Тема
без Tailwind отдаёт слой `so` верхним, и приложению со своим Tailwind нужно
поставить его раньше `components` и `utilities`, иначе база встанет над его
утилитами: как объявить порядок — README пакета.

## Сброс узлов библиотеки

`src/reset.css` — то, на что опираются части soldy, и только им: тема не
стилизует страницу (корневой `AGENTS.md`, «Темы: у пакета темы свои
инструкции»), и глобального сброса у неё нет. Выведен из
`tailwindcss/preflight.css` правило за правилом — на preflight части
опирались, пока oren подключала Tailwind целиком: правило, которое задевает
узел с классом `so-*` или его псевдоэлемент, перенесено тем же селектором,
суженным до таких узлов, с нулевой специфичностью (`:where`). Узел библиотеки
— элемент, у которого класс начинается с `so-` (`[class^='so-'],
[class*=' so-']`). Внутренние узлы без класса — поле `<input>` у Input,
CheckBox и Switch, `<textarea>` у Textarea, `<svg>` рисунка в иконке Web
Components, группы строк сетки Calendar — сброс называет через класс их
компонента (`.so-input > input`). Чего в сбросе нет:

- правил `html`, `:host` и `body`: шрифт, высота строки, `tab-size`,
  подсветка касания и отступ `body` — типографика страницы, и части берут
  шрифт приложения;
- правил на всё внутри части (`.so-x *`): содержимое слотов — узлы
  приложения. Поэтому не назван и рисунок иконки (`g`, `path`): свойства
  коробки он не читает, а свой рисунок в иконке бывает и у приложения;
- правил тегов, которых узлами библиотеки не бывает (`hr`, `abbr`, `code`,
  `img`, `select`, `summary`…), и псевдоэлементов, которых у них нет
  (`::backdrop`, `::file-selector-button`, части полей даты и числа). Ссылка
  `a` — бывает: её тегом корня ставит потребитель (`<Button tag="a">`).

У новой части узел без класса, которому нужен сброс, — строка в
`src/reset.css` через класс её компонента; правило темы на узел вне частей
уронит сторож (`sealed.spec.ts`). Что облик частей от правки сброса не
изменился, доказывает сравнение стилей стенда до и после (`npm run
compare:styles`, `packages/playground/AGENTS.md`, «Сравнение стилей»).

## Знак направления письма

Направленность письма тема читает знаком строки — переменной
`--so-dir-sign`: `1` слева направо и `-1` справа налево. Задают его правила
`[dir='ltr']` и `[dir='rtl']` в `src/direction.css`, а до блока его доносит
наследование: блок получает знак ближайшего `dir` — того же, по которому
браузер считает направленность. Без `dir` у предков — `1` от `:root`. Правило
RTL стоит ниже `:root`: у `<html dir="rtl">` совпадают оба. `dir="auto"` знака
не меняет: направленность по тексту знает только браузер, и блок под таким
предком берёт знак от `dir` выше.

Зеркало тема пишет числом — умножением на знак: масштабом (`scaleX`), углом
градиента, сдвигом. Раскладки знак не касается: логические свойства
(`margin-inline`, `padding-inline`, `inset-inline-start`) браузер считает по
настоящей направленности сам, и знак нужен только тому, у чего логических
направлений нет.

**Ловушка сборки: `:dir()` превращается в список языков.** Минификатор
сборки (Lightning CSS) берёт цели CSS-сборки Vite (`build.cssTarget`), а в
целях Vite 8 по умолчанию есть Chrome и Edge до 120, где `:dir()` ещё нет.
Поэтому он **даунлевелит** его в приближение по языку:

```css
/* исходник */
.so-scroller__viewport:dir(rtl) { … }
/* dist */
.so-scroller__viewport:is(:lang(ar), :lang(he), :lang(fa), …) { … }
```

Правило перестаёт зависеть от `dir` вовсе: арабская страница его получит, а
`<div dir="rtl">` на русской — нет. Стреляло у стрелок Scroller oren, где
зеркало обязано переезжать с одной кнопки на другую. Настроить сборку темы
мало: тот же Lightning CSS — минификатор CSS по умолчанию и у Vite
приложения, которое собирает тему у себя.

Селектор по атрибуту у предка (`:is([dir='rtl'] .so-блок,
.so-блок[dir='rtl'])`) ближайшего `dir` не видит: блок с `direction="ltr"`
или внутри `<div dir="ltr">` на RTL-странице получал зеркало RTL при
раскладке LTR. Латать селектор через `:not([dir='ltr'])` бесполезно: так
спасается только проп у самого блока, а обёртка с `dir` — нет. Поэтому
правила по `dir` есть только у знака, а тема пишет зеркала через него.

Знак у страницы без `dir` и у обоих направлений и порядок правил сторожит
`base-css.spec.ts`; что oren не пишет ни `:dir()`, ни селектора по `dir`, —
её `tokens.spec.ts`, а как зеркала встают в браузере — её браузерные спеки
(`packages/themes/oren/AGENTS.md`, «Направление письма — знаком из общего
слоя»).

## Контракт: переменные темы

Каждую переменную, которую база читает (`var()`), она объявляет сама — с
умолчанием, чтобы без темы оставаться рабочей, — или называет в
`theme-variables.json`. Это контракт базы с темой и одно место, которое
читает сторож: ключ — имя переменной `--so-*`, значение — что она значит для
темы. Лишнего в контракте нет: каждую названную переменную база читает.
Цветов в контракте нет — у базы нет облика.

Сейчас база переменных темы не читает, и контракт пуст: знак направления она
объявляет сама, а сброс переменных не читает вовсе.

## Сторожа

### Свои — по CSS базы

`__tests__/base-css.spec.ts`. Исходники читаются как есть, CSS базы —
собранным в памяти (Vite без минификации, как его вшивает тема: импорты
частей развёрнуты в их слои).

- **Чистый CSS.** В `src` только `.css`; at-правила — только CSS: `@import`,
  `@layer`, обёртки, `@keyframes`, `@property`, — так что ни директив
  Tailwind (`@apply`, `@theme`, `@utility`…), ни Sass (`@use`, `@include`…);
  ни переменных и интерполяции Sass, ни функций Tailwind (`theme()`,
  `--spacing()`, `--alpha()`).
- **Без облика.** Ни цвета — ни литерала (`#fff`, `rgb(…)`, `oklch(…)`, имя
  цвета, системный цвет вроде `Canvas`), ни ступени шкалы
  `--so-<семейство>-<ступень>`, — ни модификатора значения темы (`--view-`,
  `--variant-`, `--shape-`, `--animation-`): палитру и наборы значений
  объявляет тема. `currentcolor` и `transparent` — не цвет темы, а цвет места
  и его отсутствие.
- **Переменные — по контракту** (см. «Контракт: переменные темы»).
- **Слой.** Каждое правило базы — в слое `so` или его подслое.
- **Знак направления** задан странице без `dir` и обоим направлениям, и
  правило RTL ниже корня.

Сейчас на базе часть сторожей находить нечего (чтений переменных нет),
поэтому каждый проверен на образцах в конце файла — пустым сторож прошёл бы
на любом CSS. Проверены и поломкой: цвет, модификатор `--view-` и чтение
необъявленной переменной в CSS базы, `@apply`, переменная Sass, функция
Tailwind и правило вне слоя роняют каждый своего.

### Любой темы — по собранному CSS каждой темы

Тема — каждый пакет `packages/themes/*`, кроме самой базы
(`__tests__/themes.ts`): база входит в CSS каждой темы, и сторожа видят её
там. CSS темы собирается в памяти её же конфигом (`vite.config.ts` пакета),
тем же, что у её `build:css`: Sass, `@apply` и то, что выпускает Tailwind,
там развёрнуты, а от `dist` сторожа не зависят — шаг «Тесты» в CI идёт до
сборки. Новая тема попадает под сторожей сама; тему без `vite.config.ts`
помощник собрать не умеет и падает — её способ сборки вносится в него явно.
Пустым сторож проходит на любом CSS, поэтому каждый проверяет у oren, что ему
есть что сторожить.

**`sealed.spec.ts` — тема не стилизует страницу** (корневой `AGENTS.md`,
«Темы: у пакета темы свои инструкции»). По собранному CSS: preflight
выпускает Tailwind, и в исходниках его не видно. Каждый селектор каждого
правила вне `@keyframes` адресует узел `so-*` — класс `so-*` или атрибут
класса (`[class^='so-']`, `[class*=' so-']`) в субъекте или в предке по
цепочке, не внутри `:not()` и `:has()` и не у соседа, а в `:is()` и
`:where()` — в каждом их варианте; иначе в правиле только переменные, у
`:root` и блока схемы — и `color-scheme`. Из at-правил — только обёртки
(`@media`, `@supports`, `@container`, `@starting-style`), `@layer`,
`@keyframes` и `@property`. Что сторож считает узлом библиотеки, сверяет его
же второй раздел на селекторах-образцах. Проверен поломкой: полный `@import
'tailwindcss'` в oren роняет его на всех правилах preflight, правило на `body`
— на `body`, `html:has(.so-dialog)` — на нём же: класс внутри `:has()` —
условие на потомка, а не узел библиотеки.

**`motion.spec.ts` — движение только надстройкой** (корневой `AGENTS.md`,
«Движение: один режим на библиотеку»; критерий «что движение» —
`packages/themes/oren/AGENTS.md`, «Движение — надстройка»). Ворота движения —
пара селекторов: от `:where(:root:not([data-so-motion='reduce']))` под
`@media (prefers-reduced-motion: no-preference)` и от
`:where(:root[data-so-motion='full'])` без медиазапроса. Как тема их пишет —
её дело (у oren — миксин `motion.allowed`, и что условие режима есть только в
нём, стережёт её `motion.spec.ts` по исходникам). Здесь — собранный CSS:
`@apply` там развёрнут, и `transition-transform` видно как `transform,
translate, scale, rotate`. Вне правил ворот переход ведёт только «не
движение», анимация — только кадры «не движения» или за прокруткой,
`scroll-behavior: smooth` нет, а условие режима — только в форме ворот.
Проверен поломкой: полоса `line` oren без миксина роняет его на `transform`
и `width`.

**`keyframes-prefix.spec.ts` и `variable-prefix.spec.ts` — глобальные имена
темы в схеме `so-`**, как у библиотеки (корневой `AGENTS.md`, «Префикс —
только в глобальном пространстве имён»): кадры анимаций — `so-*`
(`so-skeleton-pulse` рядом с `so-progress-pulse`), переменные — `--so-*`:
токены, переменные компонентов и те, что пишет поведение темы. Имена
`@keyframes` у документа общие, а переменная ещё и наследуется по DOM, и
одноимённое имя приложения подменило бы имя темы — или тема его. Так брала бы
чужое геометрия Tabs oren: поведение темы пишет её на список только после
замера. Префикс — у всей категории, а не у имён, которые уже столкнулись:
переменная, которую тема объявляет на том же узле, где читает, — тоже
`--so-*`. В собранном CSS имя из интерполяции видно целиком, а модификатор
класса стоит в селекторе и за переменную не считается. Там же — то, что
выпускает Tailwind: его кадры запрещены (`animate-spin` в `@apply` выпускает
кадры `spin`), а его переменные (`--spacing`, `--radius-*`, `--text-*`,
`--font-*`, `--default-*`, `--color-*`, служебные `--tw-*`) и
`--lightningcss-*` сторож переменных пропускает списком
(`packages/themes/oren/AGENTS.md`, «Открытые вопросы»). Поведение темы
(`setup/` её пакета) сторож переменных читает строками: константа имени и
аргумент `setProperty`; модификатор класса он узнаёт по месту — аргументу
метода `TClasses` (`classes.add('--ready-animation')`), как сторож библиотеки
`packages/setup/__tests__/css-variable-prefix.spec.ts`. Проверены поломкой:
кадры волны Skeleton без префикса и `animate-spin` в `@apply` роняют сторожа
кадров, переменная Label без префикса в стилях и признак переезда Tabs без
префикса в поведении — сторожа переменных.

**`disabled.spec.ts` — прозрачность выключенного ложится на поддерево один
раз** (`packages/themes/oren/AGENTS.md`, «Выключенное гаснет целиком»):
погасший узел берёт её из переменной `--so-disabled-opacity`, а детям ставит
её единицей. По собранному CSS: в правиле, где `data-disabled` или
`:disabled` стоят вне `:not(…)`, прозрачность — только из этой переменной и
одним значением на тему. Своя прозрачность в правиле выключенного — число,
`opacity-50`, сброс `opacity-100` у части — легла бы под погасшим предком
второй раз.

**`label-hover.spec.ts` — контрол в подписи `Label` подсвечивается и от
наведения на её текст** (`packages/themes/oren/AGENTS.md`, «Наведение по
контексту подписи»): у каждого правила наведения CheckBox, Switch и радио
контекст `:where(.so-label:hover > .so-label__control *)` стоит альтернативой
`:hover` в том же `:is(…)` — так специфичность правила не меняется. Сторож по
собранному CSS, хотя поведение браузерное: Chromium, который возит
Playwright, наведение на подпись полю отдаёт сам, и `test:layout` без правила
темы остаётся зелёным — подсветка пропала бы только у пользователя.

**`table-reorder.spec.ts` — правила тела Table под признаком жеста**
(`packages/themes/oren/AGENTS.md`, «Правило на каждую ячейку — под признаком,
которого на покое нет»). По собранному CSS: у каждого правила ячейки на номер
колонки (`.so-table-row__cell:nth-child(`) цепочка предков — ровно «корень с
`data-reorder-preview` > тело > строка», переход сдвига ячеек — под тем же
признаком, `:has()` с `:nth-child(` стоит только у шапки, а у корня в
правилах под признаком `:has()` нет вовсе. Что идёт переходом, ячейка берёт
только из переменной тела (`--so-table-body-transition`, без неё — `none`), а
ставит её тело по `:has()` шапки со взятым заголовком: колонка встаёт одной
перерисовкой, но посреди неё браузер может пересчитать стиль, когда меток на
заголовках уже нет, а признак корня ещё есть, — и переход под одним
признаком корня вёл ячейки соседей от сдвига к нулю. Сдвиг, переход и
скрытие линии по взятому заголовку — не при `data-still`. Второй раздел — у
корня таблицы `:has()` нет ни в одном правиле: ни в своём компаунде, ни в
`:where()` и `:is()` (окно `.so-table__viewport:has(> .so-table…)` — не
