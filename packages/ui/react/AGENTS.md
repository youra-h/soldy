> Читается перед задачей в `packages/ui/react` (см. «Где остальное» в корне).
> Сквозные правила — в корневом `AGENTS.md`; здесь — почему адаптер React
> устроен так, а не проще. Шапки файлов ссылаются сюда:
> «AGENTS.md (React), «<раздел>»».

## React-специфика

### Сборка компонента

- Компонент собирает контексты хуком сборки `useSetup<Имя>` в
  `setup.component.ts`, разметка — в `<Имя>.tsx`. Сборка одного контекста —
  `useComponent((create, elevator) => create(XDescriptor(), { ctrl, props }).use(…), props)`:
  результат — связка `useAdapter` и слой лифта `layer`. Контекст собирает
  фабрика в месте вызова, а не `useComponent` по дескриптору: тип связки
  выводится там, и `.d.ts` хука сборки можно назвать — выведенный внутри
  обобщённого хука, он ссылается на внутренние типы `@soldy-ui/setup`
  (TS2883) или не сериализуется вовсе (TS7056). Владелец коллекции и элемент собирают два контекста —
  свой и фасада — фабрикой `useAdapterContext`, а связывает их
  `useCollectionAdapter(useAdapter(adapter, props), facade, props)`: `ctrl` и
  корень — компонента, состояние — обоих, в DOM — то, что не съели ни
  компонент, ни фасад. Фасад собран на инстансе владельца и общем наборе,
  поэтому контексты пересобираются и уничтожаются вместе. У `Menu.Submenu` фасадов два, и вызов вложенный. `RadioGroup.Item` берёт из
  фасада только `active`: `order` увёл бы радио по чужому флекс-ряду. Тост
  отдаёт раскладке корня состояние поимённо (`{ classes, visible }`): его
  `order` — глубина в стопке, и уходит она стиль-выходом `--so-toasts-depth`,
  а не CSS-свойством `order`.
- Окно обёртки `Virtual` (`TVirtualCollectionExtension`) фасад подхватывает
  при сборке, на обёртку подписывается при коммите, снимает — с
  уничтожением.
- Хуки сборки (`useSetup<Имя>`) — не публичное API: из пакета они не
  экспортируются.

### Срок жизни контекста

`useAdapterContext` (`src/adapter/runtime/`) держит контексты между
рендерами и отвечает за весь срок их жизни.

- **Держит в `useRef`**, а не в `useState` или `useMemo`: их инициализатор
  React 19 под StrictMode зовёт дважды, и второй контекст с живым набором
  плагинов утёк бы, а кэш `useMemo` React вправе сбросить.
- **Собирает функцией `create`**, которую отдаёт фабрике: это
  `createAdapterContext` с id монтирования от `useId` (счётчик процесса на
  сервере общий для всех запросов, `useId` выводится из места в дереве) и
  локалью ближайшего `LocaleProvider`. Id один у всех контекстов компонента и
  у пересобранного: место в дереве то же.
- **Лифт.** Вторым аргументом фабрика получает фабрику лифтов: `up()` читает
  слой, который компонент увидел на рендере, `down()` пишет в слой
  компонента, детям его отдаёт `Elevate`. Контекст React один на все ключи —
  неизменяемая карта (`ElevatorContext`): сборка читает лифт и при
  пересборке в эффекте, где хуков нет. Сменилось прочитанное сборкой —
  например, владелец коллекции пересобран с новым движком, — компонент
  собирается заново (`TReactElevatorScope.isStale`).
- **Уничтожает очистка эффекта.** React вправе заново установить эффекты
  живого компонента (StrictMode, `<Activity>`); его контексты к тому времени
  уничтожены, и хук собирает их заново фабрикой последнего рендера и
  перерисовывает компонент. Без `ctrl` инстанс новый, с `ctrl` — тот же.
- **Принимает при коммите** (`attach()` в том же эффекте): отброшенный
  рендер не трогает чужого, поэтому элемент входит в коллекцию только здесь.
  Эффекты детей идут раньше родителя и в порядке документа — элементы
  разметки входят в коллекцию в порядке DOM.
- **Черновики.** Отброшенный рендер React не объявляет, а плагины его сборки
  уже подписаны на `ctrl` и движок коллекции. `TDrafts` помнит непринятую
  сборку по тому, что она взяла снаружи, и следующая сборка того же `ctrl`
  или движка сначала уничтожает её. Повтор над тем же `ctrl` берёт id
  монтирования выброшенного: иначе плагины писали бы в `ctrl` новые `id` на
  каждый повтор, и живое монтирование перерисовывалось бы без конца. Движок
  без `ctrl` id не передаёт: два живых компонента на одном движке законны.

### Функции дольше рендера — в классах

Функция, которая живёт дольше рендера, — стрелка в поле объекта класса:
очистка эффекта сборки (`TBuilt.destroy`), приёмник событий
(`TEventCallbacks.sink`), ref корня (`TRootRef`), ref места `Teleport`
(`TTeleportWrapper`). Эффект с устойчивыми зависимостями хранит очистку
первого коммита всё монтирование, а замыкание держит всю область вызова —
V8 заводит одну на все замыкания вызова, — с пропсами своего рендера. Функция
модуля не спасает: вызванную один раз, минификатор потребителя встраивает
обратно (Terser, `reduce_funcs`), а класс в чужую область он не переносит.
Сторож — `__tests__/first-render-props.spec.tsx`; подробности — корневой
`AGENTS.md`, «Адаптер обязан адаптировать», и `benchmarks/table.md`.

### Связка и состояние

- **Состояние** — `useSyncExternalStore` над связкой: рендер по снимку,
  подписка при коммите, React сам сверяет снимок после подписки.
- **`TStableSnapshot`.** Ядро собирает составное значение заново на каждое
  чтение, а React читает дважды — на рендере и при подписке. Сменившееся
  значение сверяется с прежним по содержимому, вглубь простых объектов и
  массивов; совпало — остаётся прежний объект. Иначе каждый компонент
  перерисовывался бы сразу после монтирования, строка таблицы — со всеми
  ячейками. Сторож — `stable-snapshot.spec.tsx`.
- **Входы** — эффектом `binding.inputs.full(props)` на каждый рендер
  родителя: связка пишет только сменившееся, повтор не откатит записанное
  ядром или кодом через инстанс.
- **События** — колбэкам-пропсам последнего рендера, подписка
  layout-эффектом: до первой отрисовки, `ready` из `TElementPlugin` не
  теряется.
- **Пересобранный контекст** приходит новым объектом, и связка, снимок и
  приёмник событий заводятся заново (`useReducer` в `useExchange`).
- **Граница перерисовки** — `withRenderBoundary` (`memo`): компонент под ней
  родитель перерисовывает, только когда сменился проп по идентичности.
  Держит, пока родитель отдаёт те же объекты: значение из состояния
  остаётся прежним объектом (`TStableSnapshot`), слот — как пришёл. `?? []`,
  спред или стрелка-обёртка слота отключают границу молча. Сравнения по
  содержимому нет намеренно. Слот `cell` таблицы держит границу ячеек, пока
  потребитель отдаёт его одним объектом: стрелка в его разметке
  перерисует ячейки всех строк на каждый его рендер, но не на выбор.

### Корень и `ref` потребителя

- **`TRootRef`** — ref корня: узел привязывается к `TElementPlugin`, и тот же
  узел получает `ref` потребителя — так, как отдал бы React (функции —
  узлом, при снятии — её очисткой или `null`; объекту — в `current`). Ref
  корня между рендерами один: новую функцию React снял бы и привязал заново,
  и плагин объявил бы тот же узел парой `removed` + `ready`. Сменившийся
  `ref` потребителя класс получает раньше привязки ref узлов
  (`consume`, insertion-эффект) и сверяет после (`sync`, layout-эффект).
- **Уничтоженный контекст ref отпускает** — и контекст, и `ref`
  потребителя, и подписчиков: React хранит ref в узле своего дерева, а
  снятый узел живёт дольше размонтирования (`return_targetInst` событийной
  системы). Уничтожение класс слышит слушателем всех событий шины
  (`listen`), а не `on('destroy')`: слушатель — массив из одного элемента,
  подписка заводит карту наборов на каждый контекст.
- **Корень значением** — `useRootElement(root)`: подписка на ref корня,
  `null` на сервере и до коммита. Зовёт её только разметка, которой корень
  нужен значением (якорь панели Popover, Tooltip, Menu, Select, DatePicker),
  — подписка у всех перерисовывала бы каждый компонент после монтирования.
- **Раскладка корня** (`src/adapter/common/root.ts`) — в одном порядке у
  всех: наборы ядра, поверх атрибуты потребителя, класс — ядра и
  потребителя, стиль — раскладка плагина, стиль-выход компонента, `order`,
  стиль потребителя и поверх всего `display: none` скрытого (как `v-show`);
  `ref` адаптера последним — `ref` потребителя из атрибутов выбил бы
  привязку к `TElementPlugin`. Имена стиля ядро и плагины пишут по-CSS, React
  ждёт camelCase: к числу под незнакомым именем он допишет `px`
  (`toReactStyle`). HTML-имена атрибутов (`tabindex`, `for`, `readonly`…) —
  в имена пропсов React (`toAriaProps`).
- **Поле и коллекция делят атрибуты потребителя**: корню — класс и стиль
  (`toRootForward`), остальное — `<input>`, строке элемента или узлу списка с
  ролью (`toControlAttrs`). `ref` потребителя — всегда корень. Окно таблицы
  — обёртка вокруг корня `table` (`toWrappedRootProps`): обёртке — класс,
  стиль, `ref` потребителя и скрытие, корню — остальное; ref корня там —
  `bindRef`, только привязка.

### Поля ввода

`NativeInput` и `NativeTextarea` — неуправляемые поля, чьё живое состояние
ведёт ядро. Контролируемое поле без `onChange` React считает ошибкой, а
`onChange` писал бы значение вторым путём рядом с плагинами ввода;
`indeterminate` атрибутом не выразить вовсе. Умолчание идёт в разметку
(`defaultValue`, `defaultChecked`) — оно есть в серверной разметке, свойство
— в узел layout-эффектом. Текст — только если разошёлся с узлом: запись того
же сбросила бы каретку и прервала IME. Отметка — и совпавшая: React узнаёт
отметку только по записи свойства, а у радио её снимает и браузер, и без
записи следующий выбор не дал бы `onChange`. Скрытое поле формы NumberInput
без числа получает `value=''`, а не `undefined`: иначе первое число сделало
бы неуправляемое поле управляемым. Части поля даты — `contentEditable` с
`suppressContentEditableWarning`: детьми части ведает ядро — текст приходит
строкой, и React пишет её целиком.

### Teleport

`Teleport` — аналог `<teleport :to>`. Портал React переиспользует содержимое,
только пока контейнер тот же, поэтому контейнер один на всё монтирование —
обёртка `div` с `display: contents`, — а двигается сама обёртка: в цель, с
`disabled` — в узел места, без цели — вон из документа. Фаза только растёт:
«нет» (на сервере и при гидратации без `disabled`, на клиенте — пока нет ни
цели, ни `disabled`), «на месте» (дети как их нарисовал сервер, только после
серверной разметки), «в обёртке» (навсегда). Панель, начавшая на месте после
серверной разметки, при первом уходе собирается заново один раз. Фаза —
состояние React, пишет её рендер: отброшенный рендер её не сдвинет. В цель
обёртку кладёт insertion-эффект, на место — ref узла места: оба до ref
панели. Портал сервер не поддерживает; клиента от сервера отличает снимок
`useSyncExternalStore`.

Портал React сохраняет контекст: элементы в телепортированной панели видят
слой лифта владельца. На сервере портала нет — панелей и их элементов в
серверной разметке нет, элементы разметки входят в коллекцию после
гидратации.

### Слоты

Слот без scope принимает узел, со scope — ещё и функцию (`renderSlot`).
Пустое, что React не рисует (`null`, булево), отдаётся как `undefined`, и
встаёт запасное содержимое (`renderSlot(…) ?? text`): `{cond && <Icon />}` не
глушит текст кнопки. `hasSlot` — аналог `$slots.x`. Проброс слота владельца
элементу — функция (`relaySlot`), добавляющая элемент к scope элемента:
готовый узел терял бы `text`, `selected` и `active` элемента. Слота у
владельца нет — проброса нет (`undefined`), и элемент рисует своё. Функцией
отдаются только слоты со scope элемента; края без него (`item-leading`,
`item-trailing`, `item-close-icon`) владелец рисует сам, с элементом в scope.
Ячейка таблицы без слота рисует `cell.text`, а не `cell.value`: объект React
не нарисует, а булево и `null` пропустит.

Компонент-тег у `Icon` (`roleIcon` и свой) обязан положить на свой корень
`ref`, класс, стиль и ARIA: без `ref` не придёт `element:ready`, без класса и
стиля пропадёт размер, без ARIA иконка перестанет быть скрытой.

### Пересобранный инстанс и `key`

Экземпляр, которым владеет компонент (поле Select и DatePicker, теги поля,
календарь), — сборки: без `ctrl` пересобранный компонент (StrictMode,
`<Activity>`) — новый инстанс с новыми частями. Разметка ставит вложенный
компонент над ними с `key={part.uid}`: компонент собирается над `ctrl` один
раз за монтирование и иначе остался бы над прежним. Свои части в слотах
ставят тот же ключ. Так же — экземпляры, которые выдаёт владелец коллекции:
чекбокс строки таблицы (`key={checkBox.uid}`) строка получает от
item-адаптера на монтирование своего контекста, и пересобранная строка
берёт новый; «выбрать все» (`key={selectAll.uid}`) у пересобранной таблицы
без движка снаружи — новый.

### Клик элемента и клик потребителя

Элемент коллекции, чьё действие висит на клике (таб, секция Accordion,
элемент ListBox, пункт меню), вынимает `onClick` из атрибутов потребителя и
зовёт его после своего действия — замена слиянию слушателей у Vue. Крестик
таба и тега гасит всплытие у нативного события в `onActionClick`, а не
синтетическим `stopPropagation`: синтетическое событие к этому моменту уже
прошло корни таба и набора, и их `TActionPlugin` отдал бы `action:press`.
Так же кнопка очистки поля (Input, NumberInput, DateInput, DatePicker): иначе
клик по ней дошёл бы до корня select-only Select и открыл панель. Выбор радио
приходит `onChange` нативного поля — браузер уже отметил его и снял отметку
с соседа; адаптер активирует элемент и зовёт `onChange` потребителя.

### Локаль и тосты

- `LocaleProvider` держит источник в `useState`: лишний инициализатор
  StrictMode уходит сборщику — подписок у источника нет. Новую локаль пишет
  layout-эффектом, не на рендере: запись будит подписчиков других
  компонентов. Источник один на провайдер, не на процесс: сервер рисует
  параллельные запросы на своих языках.
- `useToasts()` берёт API лифтом из слоя, который компонент видит на
  рендере. Пересобранный менеджер без движка снаружи — новый API, поэтому
  `show` — в зависимостях эффекта. Менеджера выше нет — ошибка. Своё
  содержимое тоста — компонент React (функция, класс, `memo`, `forwardRef`,
  `lazy`), не готовый элемент: проп `toast` тост отдаёт сам (`isToastRender`).

### Типы пропсов

`TDomAttributes` (`src/types.ts`) — атрибуты корня без входов, событий и
слотов дескриптора: вход важнее одноимённого атрибута (`content` RDFa,
`onInput` DOM), `children` вычитается всегда (содержимое — только слот
`default`), защищённые пропсы — тоже (их раздаёт владелец). `ref` ведёт к
корню, узел — `Element`. Поля берут `TFieldAttributes` и
`TTextareaAttributes`: без того, что поле ведёт само (текст, отметка,
`readOnly`, `maxLength`).
