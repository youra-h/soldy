# Замеры производительности

Как таблица soldy держит большой объём рядом с таблицами других библиотек. Файл —
журнал: новый замер дописывается новым разделом, старые не переписываются, чтобы
было видно, что дала каждая правка.

## Стенд

[`tools/bench-table/`](tools/bench-table/) — Vite-страница и прогонщик на Playwright.
Вне workspaces: зависимости других библиотек ставятся только в стенд и в монорепо не
попадают.

```bash
cd tools/bench-table
npm install                    # один раз: таблицы других библиотек
npm run bench -- 5000 3        # строк, прогонов, [библиотеки через запятую]
npm run bench -- 5000 3 soldy  # только наша таблица
npm run bench -- 5000 3 soldy+mode=none+cols=5  # флаги через «+»: без выбора, 5 колонок
npm run prof                   # профиль CPU soldy без минификации (5000 строк)
npm run heap -- 500 multiple   # снимок кучи soldy: что весит в строке; режим — multiple | none
npm run trace -- 5000 soldy+reorder 3  # трасса жеста перестановки: строк, [библиотеки], [прогонов]
```

`trace.mjs` рисует N строк и прогоняет три сценария перестановки — «Взять колонку», «Смена места»
и «Отпустить», — каждый под своей трассой Chromium (`browser.startTracing`). По сценарию он печатает
медиану сумм фаз главного потока: пересчёт стилей (`UpdateLayoutTree`), раскладку (`Layout`), обход
перед отрисовкой (`PrePaint`), отрисовку (`Paint`) и перестройку слоёв (`Layerize`), — отдельно
пересчёт стилей внутри обработчиков указателя (синхронный, вызванный чтением после записи) и
наибольшее число элементов, чей стиль пересчитан за раз. Флаги — те же, что у `run.mjs`.

`heap.mjs` снимает кучу дважды на одной странице, с пустой таблицей и с N строками, и
делит разницу на N. Разницу он раскладывает тремя способами: по конструкторам, по
первому владельцу внутренних узлов (массивы, контексты замыканий) и по ближайшему
«хозяину» в дереве доминаторов — классу soldy, экземпляру или VNode Vue, `Dep`. У
замыканий указана строка несжатой сборки (`dist-prof`). Узел, который держат двое,
относится к хозяину первого держателя, поэтому раскладка по хозяевам приблизительна.

- `libs/data.ts` — данные и колонки, общие для всех: детерминированный генератор,
  20 колонок, `name` — строка, остальные — числа.
- `libs/<библиотека>.ts` — таблица библиотеки и селекторы её чекбокса «выбрать все» и
  заголовка сортировки. Новая библиотека — новый файл и строка в `main.ts`.
- Ориентиры без готовой таблицы: `plain` — голый Vue (`libs/PlainTable.vue`: `v-for`,
  нативные чекбоксы, выбор в реактивном `Set`), `tanstack` и `reka` — TanStack Table v9
  (`libs/TanstackTable.vue`) с нативными чекбоксами и с `CheckboxRoot` из Reka UI (так
  устроена Data Table shadcn-vue).
- `core` — опыт «ядро без проводки» (`libs/CoreTable.vue`): коллекция таблицы soldy
  (`TTableCollectionFacade`, фасады строк, их `cells`), а рисует её голый `v-for` без
  компонентов строк, адаптерных контекстов и обмена.
- Флаги участника — через «+»: `virtual` — окно (таблица в обёртке `Virtual`), `mode=none` — без выбора (сценарии
  выбора пропускаются), `cols=5` — только первые колонки. У soldy ещё `reorder` — колонки можно переставлять
  (`reorderable`), и после сортировок идут три сценария перестановки: «Взять колонку», «Смена места» и «Отпустить»
  (замер — пока колонка не встала); `preview=column` — за жестом идут и ячейки строк (`reorderPreview: 'column'`),
  `preview=none` — шапка стоит (`reorderPreview: 'none'`); `motion=reduce` — без движения (`useMotion('reduce')`).
  Без флагов таблица и сценарии те же.
- `main.ts` — сценарии (`window.bench`), `run.mjs` — прогонщик и итоговая таблица.

## Методика

- Продакшн-сборка, Chromium (Playwright), окно 1600×1000. Новая страница на каждый
  прогон, в таблице — медиана.
- Время — от действия до момента, когда кадры снова идут чаще, чем раз в 50 мс, три
  кадра подряд: в него входят асинхронные досчёты библиотеки, а не только первый кадр.
- Действия — настоящие клики в DOM: чекбокс «выбрать все» в шапке, заголовок первой
  колонки. Перестановка — события указателя мыши из кода (`PointerEvent`) по заголовку
  второй колонки: нажатие и протяжка за порог жеста, шаг за середину третьей,
  отпускание.
- Память — прирост `usedJSHeapSize` после принудительной сборки мусора.
- У всех настройки по умолчанию, виртуализация выключена, ячейки — текст без своих
  рендереров. Прогонщик проверяет, что действие выполнилось: число отмеченных строк и
  первая строка после сортировки.

## 2026-10-09 — Vue, память строки

[869fekb4g](https://app.clickup.com/t/869fekb4g). Сначала — разбор снимком кучи
(`npm run heap`), потом правки в адаптере Vue, на которые он указал.

### Что изменилось

Три правки в адаптере Vue, вклад каждой — снимком кучи по очереди (КБ на строку):

| Правка                                                                                         | `multiple` |
| ---------------------------------------------------------------------------------------------- | ---------- |
| `main`                                                                                         | 143,8      |
| Рефы состояния мелкие (`shallowRef`): значения ядра без прокси и зависимостей на каждый ключ   | 116,8      |
| Один `watch` на все входы компонента вместо `watch` на каждый проп                             | 103,4      |
| Ячейка — `<component :is>` с текстом внутри: два узла Vue на ячейку вместо четырёх с половиной | 95,5       |

В `mode="none"` — 55,2 КБ вместо 92,2.

## 2026-10-09 — Vue, окно — прокрученные строки памяти не держат

## 2026-10-09 — Vue, шина платит за подписку, обмен — один слушатель на участника

[869ff057c](https://app.clickup.com/t/869ff057c), PR
[#368](https://github.com/youra-h/soldy/pull/368). Пересмотр механизмов обмена и
событий, согласованный с владельцем:

- **шина ядра** (`TEvented`) заводит эмиттер, перехватчики, слушателей и пробросы при
  первом использовании и снимает с последней отпиской — шина без подписчиков стала
  одним объектом;
- **обмен** слушает шину каждого участника одним слушателем всех событий
  (`TEvented.listen`), общим для состояния и событий, а не маршрутом `on` на каждое
  событие поверхности и подпиской на каждый триггер свойства. Что делать с событием,
  говорит таблица маршрутов типа — одна на все монтирования;
- ячейки состояния и входов обмена без подписчиков: порт действует по ответу `set()`.

### Что осталось

Обмен и шины — около 20 КБ на строку из 61:

- подписки `on` плагинов и самого ядра — около 17 эмиттеров на строку и 6 КБ: эти
  события действительно слушают;
- линии и ячейки состояния и входов — около 4 КБ, по ячейке на свойство с триггером и

  подписывает на источник первый подписчик фасада;
- слушатели участников, состояние и приёмники обмена — около 4 КБ.

Остальное в строке — разметка и реактивность Vue (VNode, `Dep`, `Link`, рефы — около
25 КБ), экземпляры Vue, адаптерные контексты, плагины и модель ядра. До ядра без
проводки (0,82 с, 53 МБ) это не доведёт: остаются два компонента на строку.

## 2026-10-10 — Vue, жест перестановки в `head` — как до живой перестановки

[869ffc5mv](https://app.clickup.com/t/869ffc5mv) и [869ffap5j](https://app.clickup.com/t/869ffap5j),
PR [#388](https://github.com/youra-h/soldy/pull/388). После живой перестановки (раздел выше) жест в
`head` на 5000 строк × 20 колонок без окна стоил вдвое дороже прежнего: взять колонку — 1,15 с против
0,53, смена места — 0,40 с против 0,16. Куда уходит время, показала трасса жеста — новый скрипт
стенда `npm run trace` (см. «Стенд»). Причин три.

1. **Пересчёт стилей в обработчике указателя.** Плагин жеста писал корню ширину взятого — наследуемую
   переменную, то есть новый стиль всем 125 тыс. элементам, — а следом читал стиль корня (направление
   строки) и его коробку. Браузер пересчитывал стиль синхронно, прямо в обработчике (~260 мс), и ещё
   раз в кадре — там его будит курсор «тащу» на корне по `:has()`, он есть и до живой перестановки.
   Теперь ширина лежит там, где её читают: на шапке в `head` (тело её не читает), на корне — только в
   `column`; в обработчике сначала чтения — снимок, направление строки, место, — потом записи, а
   направление строки берётся из снимка.
2. **Перестройка слоёв (`Layerize`) ~350 мс на взятии и на каждой смене места.** Чекбокс строки
   (`relative`) и его поле (`z-10`) рисовались после заголовков, и заголовок, ставший своим слоем, —
   сосед с переходом сдвига, приземление взятого, — сверялся на каждой перестройке слоёв с каждым из
   них. Проверка: без колонки выбора (`soldy+reorder+mode=none`) `Layerize` смены места — 0 мс,
   взятия — 17. Теперь шапка поднята над телом всегда (`relative z-30`, как была у закреплённой) и
